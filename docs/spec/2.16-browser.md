# 2.16 Model Browser and history editing

Status: ✅ done (checked visually) · 🟡 partial / waiting for a visual check · ⬜ to do · ⛔ blocked.

## 1. Purpose

The browser shows the part's history — sketches and features in the order in which they are
built — and is the main place for editing it: rolling back with the *End of Part* marker,
inserting new features in the middle, reordering by dragging, suppressing (Suppress), deleting
with options, renaming. The goal is that the owner can add features in the middle of the model
and edit comfortably, as in Inventor.

## 2. Inputs

- A row in the browser (feature, sketch, *End of Part*); left, double and right click; dragging; F2.
- Data: `PartDocument::features` (the history), `PartSketch::after_features` (the place of a
  sketch), `PartDocument::eop` (the marker), `PartDocument::suppressed` (the suppressed ones by id).

## 3. Layout

```text
Part1
├─ Solid Bodies (N)          bodies, the result of the features
├─ Origin                    YZ, XZ, XY, X/Y/Z Axis, Center Point
├─ Sketch1                   free sketch — at its place in the history
├─ Extrusion1                feature; expands to:
│  └─ Sketch2                  its consumed sketch
├─ Sketch2 (shared)          shared sketch — above the first feature that uses it
├─ ▬ End of Part             the marker; everything below it is "rolled back" (grey)
└─ Revolution1   (grey)
   └─ Sketch3
```

| Rule | Behaviour in Inventor (in our words) | Status |
|---|---|---|
| Order = the history | sketches and features one after another, in build order | ✅ |
| Consumed sketch | nested under its feature; a free one stays where it was created | ✅ |
| Shared sketch | both above the feature and under every one that uses it | ✅ |
| Solid Bodies | at the top, with the number of bodies (+ Surface Bodies) | ✅ |
| Empty part | starts without a sample shape | ✅ |
| Icons by kind | sketch, Box, Extrude, Revolve, Fillet, Chamfer, Shell, Draft, Pattern/Mirror, Hole, Thread, work plane/axis/point | 🟡 waiting for a visual check (the icons are the same for the whole row, now via the shared function `feature_label`) |

## 5. Dependencies (when a move is forbidden)

Feature A **depends** on feature B when one of the strings in A's definition (without `id`,
`name`, `type`, `sketch`) or in the placement and projections of its sketch is B's id (body,
pattern source, work feature) or starts with `B:` (a face, edge, vertex of B). This
catches: faces and edges by persistent name (Fillet, Shell, Draft, Thread, Hole), work
features, pattern sources, the bodies the feature modifies, and sketches on faces.

- A feature cannot go above what it depends on, nor above its sketch if that sketch is
  shared. A consumed sketch (of this feature only) moves up with it if needed.
- A sketch on a face of the moved feature goes down with it.
- The other sketches keep their place relative to the features that do not move.
- An implicit dependency (Join/Cut with no body before them) is caught by regeneration — the move
  is undone.

## 6. Edge cases and errors

| Case | Behaviour |
|---|---|
| The marker at 0 | the part is empty; new features go to the very top |
| The marker at the end | saved as "no marker" (`eop` is absent from the file) |
| Deleting a feature above the marker | the marker moves up by one position |
| A sketch created at the marker, and a feature after it | the sketch stays above the new feature |
| Edit Feature with a raised marker | builds up to the smaller of the two (`build_limit`) |
| An error in Move EOP / Suppress / Delete / Reorder | the state is restored (rule 5), message `<Command>: <reason>`, the Undo step is cancelled |

## 7. Implementation

- `src/part/history.rs`: `eop_index`, `build_limit`, `insert_index`, `last_inserted`,
  `insert_feature` (the only place where a feature is inserted; all
  `add_*` use it via `insert_feature_checked`), `set_eop`, `delete_below_eop`, `feature_refs`,
  `sketch_refs`, `dependents`, `move_feature`, `suppress_feature`, `unsuppress_feature`,
  `delete_plan`, `delete_features` (`DeleteOptions`), `rename_feature`, `rename_sketch`.
- `src/part/mod.rs`: regeneration builds up to `build_limit()`, skips the suppressed ones (their key
  does not enter the cache chain), the sketches at the stop follow the body there.
- `src/gui/panels.rs` (the browser: `feature_label`, `feature_menu`, `eop_row`, dragging),
  `src/gui/browser_edit.rs` (the commands, the *Delete Features* window, Rename).
- Cache: a step's key = the previous key + the feature + the geometry of its sketch;
  insertion, moving and suppression change the chain from their place onwards. The test
  `cache_matches_cold_rebuild_after_each_edit` compares with a cold regeneration.
- File format: revision 7 (`eop`, `suppressed`), fixture `tests/compat/r7/`.
