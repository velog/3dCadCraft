# 2.18 Simplify (part)

Status: ✅ done · 🟡 partial · ⬜ to do · ⛔ waiting for another feature.

## 1. Purpose

A lighter copy of a part for others: a supplier gets the outside shape without the bores and
rounds, a layout gets a keep-out block, a large assembly loads faster. Inventor's part
**Simplify** (3D Model › Simplification) removes features by kind and size, leaves bodies out,
and can replace bodies by envelopes. Its result is a feature at the end of the history; model
states decide where it is active.

Ours offers the three outputs the owner asked for:

- **New Model State** — a new variant (our Model States) of the same part whose Simplify feature
  is active; the other states suppress it and keep every detail. It is the master's own
  history, so the master's changes reach it, and Edit Feature changes how much it simplifies.
- **Active Model State** — the Simplify feature in the state that is active (Inventor's plain
  behaviour).
- **New Part** — a new part of the design file deriving this one simplified (a derived part,
  spec 3.10 §3.5, whose link carries the options): it follows the source on Update, and its own
  Edit changes the options.

## 2. Inputs

- **3D Model › Simplification › Simplify** (alias `SIM`), one panel.
- Bodies (Selected Bodies, Exclude) are picked in the view or the browser; Preserve takes a face
  of each feature to keep.

## 4. Browser and editing

- **Simplify1** under the history's end, tooltip = what it removes.
- Features it removes are shown suppressed (grey) while it is active.
- New Model State: the Variants window lists the new state; the Simplify feature is suppressed
  in every other state (a feature added in Member Scope is suppressed in the others).
- New Part: the new document is in Manage › Documents; its base feature is the derived import
  (Edit opens Derive; Break Link keeps the geometry).

## 5. Edge cases and errors

- Range with a maximum of 0 or less: `Simplify: Holes: the maximum size must be greater than 0`.
- Every body left out: the feature's health `every body is left out` (nothing else changes).
- Selected Bodies with none chosen: refused before the feature is made.
- A failure leaves the part as it was (rule 5): the new variant is not kept either.
- Older builds (before revision 74) cannot read a part with a Simplify feature.

## 6. Implementation

- `part::simplify`: `SimplifySpec` (every option), `SimplifyOp` (the feature), `simplify_kind`
  (kind and size of a history feature), `simplified_away` (gathered into `cond_suppressed` by
  `evaluate_parameters`, like Suppress if), `simplify_bodies` (the feature's own step),
  `add_simplify`, `add_simplified_variant`, `simplified` (a built copy).
- `kernel::exact::simplify`: envelopes (`envelope`), `fill_voids` (solidcore's void regions,
  `compat::sk::fill_voids`), `visible_from_outside` (14 directions).
- New Part: `DeriveLink::simplify` (`part::derive`), `assembly::make::simplified_part`.
- GUI: `gui/simplify.rs` (presets, OK, Edit), the panel in `gui/part_planned.rs`.
- Tests: `tests/simplify.rs` (volumes against the formulas, model state follows the master,
  Edit, save / load, New Part Update, refusals); `kernel/exact/simplify.rs` unit tests
  (envelopes, a filled void, an internal body); perf case `simplify_*` in `tests/perf.rs`.
