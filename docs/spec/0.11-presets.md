# 0.11 Presets (ready-made sets of settings in command panels)

## 1. Purpose

A preset is a named record of the settings of one feature command (Extrude, Fillet,
Shell…). The user prepares the values once ("Fillet 3 mm", "Shell 1.5 Outside"), gives
them a name and then picks them with one click: the panel is filled in at once. The
command's inputs (profiles, edges, faces, axes) are **not** part of the preset — they are
picked anew every time.

Presets are a **user setting**, not document data. They are stored in the program's
settings folder and apply to all projects. The part itself records only the **name** of
the preset the feature was made with (for Edit Feature).

## 2. Inputs

- the current values in the panel of the open command;
- the command's preset file in the settings folder;
- on Edit Feature: the preset name recorded in the feature.

### 3.3 Behaviour on start and on edit

| Option | Inventor behaviour | Restrictions | Our status |
|---|---|---|---|
| New command | the list shows **Last Used** if the command was used before, otherwise **No Preset** | | 🟡 `CommandPresets::start`; Last Used is kept between sessions |
| Last Used | a temporary preset: the last values with which OK / Apply was pressed | | 🟡 recorded on a successful OK / Apply of a new feature (not on Edit Feature) |
| No Preset | the factory values; for Extrude/Revolve the Boolean operation is the last used one | | 🟡 for us the operation stays the suggested one (Join with a body, New Solid without a body) |
| Edit Feature | shows the preset the feature was made with; if it came from Last Used / is outdated — No Preset | | 🟡 the name from the feature's `preset` (test `edit_feature_shows_the_preset_it_was_made_with`); if the preset no longer exists — No Preset |
| Old feature with changed values → Custom | | | ⬜ we show No Preset |
| Predict Boolean | the suggested operation beats the one in the preset | Extrude/Revolve | 🟡 without a body (nothing to Join/Cut) it stays New Solid |
| Built-in presets | metric and inch ones depending on the document units; read-only; can become the basis of one's own | | 🟡 metric only (our documents are in mm); basis of one's own — pick the built-in one, change it, (+) |
| Tolerances in the preset | a value's tolerance is kept with the preset | | ⬜ the feature fields have no tolerances yet |
| Surface mode | presets of features that make bodies also keep Solid/Surface | | 🟡 `output` for Extrude / Revolve |
| Conflict with a style | a preset incompatible with the style is greyed out | | ⛔ no styles |

### 3.4 What each command's preset keeps

The feature's JSON object is kept, **only** with the keys from the list. Everything else
(id, name, sketch, profiles, axis, edges, faces, bodies, the parameter names) is left out.
For expression fields the **text of the expression** is kept (`params: {"distance": "wall*2"}`),
and the value as a number. On applying, the expression is evaluated anew in the current
document; if that parameter does not exist there, the stored number stays and a warning is
shown.

| Command | Keeps | Does not keep (inputs) | Our status |
|---|---|---|---|
| Extrude | `extent` (Distance / To Next / Through All), `distance`, `distance_b`, `direction`, `taper`, `taper_b`, `operation`, `output`, the expressions | profiles, sketch, `To` face/vertex, `from`, `solids` | 🟡 test `strip_inputs_leaves_out_the_inputs` |
| Revolve | `extent`, `angle`, `angle_b`, `direction`, `operation`, `output`, the expressions | profiles, sketch, axis, `solids` | 🟡 |
| Fillet | `kind` (radius), `fillet_type`, `smooth`, `cone_corners`, the expression of `radius` | edges, the additional edge sets (`sets`), the variable radii, the middle face of Full Round | 🟡 the radii of the additional sets are not kept |
| Chamfer | `kind` (method, distances, angle, flip), `cone_corners`, the expressions | edges, the partial chamfer | 🟡 |
| Shell | `thickness`, `direction`, `chain`, the expressions | Remove Faces, `solids` | 🟡 |
| Face Draft | `draft_type`, `angle`, `flip`, `chain`, the expressions | the pull direction, the plane, the faces | 🟡 our extension: in Inventor Draft is a dialog without presets |
| Work Plane (Offset) | in Inventor work planes have no presets | | ⛔ not a command with presets in Inventor |
| Hole, Pattern | in Inventor they have presets | | ⬜ one implementation of `PresetData` for each (see §6) |

## 4. Browser and editing behaviour

- The feature keeps only the preset's name (`preset`), nothing else. If the preset is
  renamed or deleted, the feature does not change; Edit Feature shows No Preset.
- The feature's values are its own: Edit Feature does **not** apply the preset again, it
  only shows it in the list (with an asterisk if the values already differ).
- If another preset is picked during Edit Feature and OK is pressed, the feature remembers
  the new name.

## 5. Edge cases and errors

- Damaged folder or file (invalid JSON): warning `Presets: <file> is damaged
  (…); it is kept as <file>.bak at the next save`. The command works with a list without
  user presets; on the first save the old file is moved to `.bak`, not lost.
- Read-only file: warning `Presets: <file> is read-only; changes are not saved`.
  Its presets are used, the changes last until the end of the session.
- A save that fails (no permission, full disk): a warning, the program continues.
- The save is atomic: a temporary file next to the target, then a rename.
- Name: empty, already taken (also by a built-in one), `No Preset` or `Last Used` →
  `Presets: …` error, nothing changes.
- Built-in preset: Save / Rename / Delete are greyed out; called from outside — an error,
  nothing changes.
- A preset from a newer version with an unknown key: the key is skipped, the rest is
  applied.
- A value of the wrong kind (e.g. text instead of a number): applying is refused with the
  error `<Command>: the preset does not fit this command (…)`, the panel stays as it was.
- If there is no settings folder (no `APPDATA` / `HOME`), the presets live only in memory.

## 6. Implementation

- `src/presets.rs` (no GUI, tested with a temporary folder):
  - `PresetData` — a trait for a feature definition: `KEYS` (the setting keys),
    `strip_inputs` (inputs hidden in a setting, e.g. `extent: To(face)`), `capture`,
    `apply`, `preset_name` / `set_preset_name`, `to_feature` / `from_feature`;
  - `apply_in(part, def, settings)` applies and re-evaluates the expressions in the
    document;
  - `CommandPresets` — the presets of one command, Last Used, New Default, Sort, counters
    for "created / changed / used";
  - `PresetStore` — one JSON file per command (`<Command>.json` without spaces) in
    `%APPDATA%\3dcadcraft\presets` (Windows) or `~/.config/3dcadcraft/presets`;
    `CADCRAFT3D_PRESETS_DIR` redirects it (tests, scripts);
  - `builtins(command)` and `factory(command)`.
- `gui/presets.rs`: `PresetUi` (the state of the row for each command) and the hooks
  `preset_row`, `preset_start`, `preset_edit`, `preset_stamp`, `preset_used`.
- Features have a field `preset: Option<String>` (`#[serde(default, skip_serializing_if =
  "Option::is_none")]`): old versions skip it, a file without a preset is byte for byte the
  same — that is why `FORMAT_REVISION` is not bumped.
- **New command with presets** (Hole, Pattern…): `impl PresetData for HoleFeature` in
  `presets.rs` (keys + `strip_inputs`), `builtins`/`factory` for the command name, and the
  four hooks in the GUI: `preset_start` on start, `preset_edit` on Edit Feature,
  `preset_row` below the panel title, `preset_stamp` + `preset_used` on OK.
