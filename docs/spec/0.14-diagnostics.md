# 0.14 Diagnostics and recovery (log, action journal, autosave, crash report)

## 1. Purpose

The owner must be able to say "in the last session, at the end, something did not work" and
the assistant (which reads files on this machine) must be able to find out what happened:
which actions were taken, how the program responded, which feature became "sick" and
whether the program crashed. In addition, work must not be lost in a crash: the program
keeps automatic copies and offers to restore them on the next start.

Inventor has similar mechanisms: automatic saving of the open documents (Application
Options → Save), an offer to recover after an abnormal shutdown and a crash report
(Customer Error Report) that the user sends. Our version is more transparent: everything
is in plain text files that the assistant can read and turn into a test.

## 2. Inputs

- the user's actions (every change goes through `CadCraftApp::checkpoint`, rule 4);
- the commands with a dialog (Extrude, Fillet, Shell…): open, OK, Cancel;
- the status-bar messages (`file_status`), the health of the features after regeneration;
- the open project (for autosave and for the diagnostics bundle).

## 3. Options and behaviour

Data folder (`<root>`): `%APPDATA%\3dcadcraft` on Windows, `~/.config/3dcadcraft` on
Linux; `CADCRAFT3D_DIAG_DIR` replaces it (for tests and development). All times are in UTC.

### 3.3 Replay

**Decision:** snapshots are **JSON deltas**, not compressed full copies. The part is
serialized **without the body** (it is a cache of the features and is built again), and
only the difference from the previous snapshot is written: an unchanged feature or sketch
costs a few bytes (`{"s":3}`), a changed value — the path to it. Every 25th snapshot is full
(`{"v":…}`), so that not everything is lost on a damaged line. A snapshot over 8 MB or a
journal over 256 MB → `snap_skipped` (replay stops there until the next full snapshot).
Only the active part is recorded.

| Option | Behaviour | Restrictions | Our status |
|---|---|---|---|
| `diagnostics::replay::replay(path)` | applies the deltas line by line, regenerates after each and compares with `result` | volume with relative accuracy 1e-6, number of faces, sick features | 🟡 test `a_recorded_session_replays_to_the_same_volume` (box, Extrude, Fillet, Shell) |
| First difference | `first_difference(&steps)`: the first step that does not reproduce (or cannot be applied) | | 🟡 test `a_step_that_does_not_reproduce_is_reported` |
| Damaged / cut-off line | the last cut-off line (crash) is skipped; a damaged one in the middle is a step error | | 🟡 test `damaged_and_cut_off_lines` |
| The part at step N | `part_at(path, N)`; `cargo run --example replay -- J --part N out.3dcadcraft` | | 🟡 |
| CLI | `cargo run --example replay -- path` prints every step and marks the first difference (exit code 1) | | 🟡 `examples/replay.rs` |
| Regeneration cache | the steps share `BuildCache`, as in the session | | 🟡 |

### 3.4 Autosave and Restore

| Option | Behaviour | Restrictions | Our status |
|---|---|---|---|
| When | every 5 minutes and after a successful OK of a feature, if at least 30 s have passed since the last autosave | only if the project has unsaved changes **and** has changed since the last autosave | 🟡 `recovery::Autosaver`, test `autosave_only_when_dirty_and_keeps_three` |
| Never during a command | nothing is saved while a feature dialog (preview), a drag or Edit Feature (rollback) is open | | 🟡 `gui/diag.rs::diag_busy` |
| Where | `<root>/recovery/<project>-<hash>-<time>.3dcadcraft` + `<file>.json` (the original path, time, session, kind) | the hash is of the path (or of the project id if it was never saved) | 🟡 atomic (`Project::save` + `write_atomic`), in a background thread with a copy of the project |
| How many | the last 3 per project | | 🟡 `recovery::prune` |
| The user's file | is **never** overwritten automatically | | 🟡 |
| Clean exit | on a normal close the session description (`session-….json`) gets `clean_exit: true` | a crash / killed process leaves `false` | 🟡 `diagnostics::finish` in `main.rs` |
| Offer at start | if the previous session did not close cleanly and one of its autosaves is newer than the original file (or the project was never saved / the file is missing): a **Restore** window — "Restore the autosaved version of …?" with **Restore** / **Open Original** / **Discard** | only the previous session's autosaves are offered; two running instances of the program are not told apart | 🟡 `recovery::offers`, test `restore_is_offered_only_after_an_unclean_exit_for_newer_autosaves`; waiting for a visual check |
| Restore | opens the autosave; the path becomes the original one, the project is "unsaved" (`*`), saving is up to the user | | 🟡 `restore_autosave`; waiting for a visual check |
| Open Original | opens the original file; the autosaves stay (they are deleted by the rotation) | greyed out if the original is missing | 🟡 |
| Discard | deletes the project's autosaves from that session | | 🟡 test `discard_deletes_the_files` |

| Option | Behaviour | Restrictions | Our status |
|---|---|---|---|

| Expected panics | panics caught by the kernel guard (`crash::guard` in `kernel::exact`) are only a line in the log — they already become feature errors | | 🟡 test `guarded_panics_are_caught` |

## 4. Browser and editing behaviour

There is nothing in the model browser. The journal records Edit Feature as the command's
`command_start` / `command_ok` and a snapshot after OK. During Edit Feature (rollback) no
snapshots and no autosaves are made.

## 5. Edge cases and errors

- No data folder (no `APPDATA`/`HOME`): log only to stderr, no journal and no autosave.
- The log / journal file cannot be opened: a warning on stderr, the program keeps working.
- Autosave fails: a line `autosave failed: …` in the log; the next attempt follows the schedule.
- Panic while writing to the log: the hook does not wait for the lock (`try_lock`).
- A panic inside the hook leads to an abort (a Rust rule) — that is why its code contains no `unwrap`/`panic`.

## 6. Implementation

- `src/diagnostics/mod.rs` — `root`, `start`/`finish`, `open_session`, `rotate`, `write_atomic`, time (UTC without external libraries), a stable hash (FNV-1a).
- `log.rs` — the logger; `journal.rs` — the journal, `diff`/`apply`, `Outcome`; `replay.rs`; `recovery.rs`; `crash.rs`; `bundle.rs`.
- `src/gui/diag.rs` — the GUI hooks (one method per frame, `diag_frame`), the Restore window, the Help menu; `gui/files.rs` — `DialogPurpose::Diagnostics`.
- `main.rs` — `diagnostics::start` before eframe, `diagnostics::finish` after closing.
- Other hooks: feature time over 200 ms (`part::build_features`), save/open (`document::format`), export (`part::export`), preset warnings.
