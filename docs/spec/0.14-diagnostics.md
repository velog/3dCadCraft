# 0.14 Диагностика и възстановяване (лог, дневник на действията, автозапис, доклад за срив)

## 1. Предназначение

Собственикът трябва да може да каже „в последната сесия, накрая, нещо не проработи“ и
асистентът (който чете файлове на тази машина) да разбере какво се е случило: какви
действия са направени, какво е отговорила програмата, коя операция се е „разболяла“ и
дали програмата е паднала. Освен това работата не бива да се губи при срив: програмата
пази автоматични копия и при следващото стартиране предлага да ги възстанови.

Inventor има сходни механизми: автоматичен запис на отворените документи (Application
Options → Save), предложение за възстановяване след аварийно затваряне и доклад за срив
(Customer Error Report), който потребителят изпраща. Нашата версия е по-прозрачна: всичко
е в обикновени текстови файлове, които асистентът може да прочете и да превърне в тест.

## 2. Входни данни

- действията на потребителя (всяка промяна минава през `CadCraftApp::checkpoint`, правило 4);
- командите с диалог (Extrude, Fillet, Shell…): отваряне, OK, Cancel;
- съобщенията в лентата на състоянието (`file_status`), здравето на операциите след регенерация;
- отвореният проект (за автозапис и за пакета с диагностика).

## 3. Настройки и поведение

Папка на данните (`<root>`): `%APPDATA%\3dcadcraft` под Windows, `~/.config/3dcadcraft` под
Linux; `CADCRAFT3D_DIAG_DIR` я заменя (за тестове и разработка). Всички времена са в UTC.

### 3.1 Лог на сесията

| Опция | Поведение (Inventor / нашето решение) | Ограничения | При нас |
|---|---|---|---|

|---|---|---|---|

| `command_start` / `command_ok` / `command_cancel` | отваряне и край на диалог на операция; OK носи `dur_ms`, определението на новата/сменената операция (`feature`, JSON) и резултата (`ok` или `{"sick": …}`) | OK = операциите са се променили, иначе Cancel | 🟡 `gui/diag.rs::diag_commands` (наблюдава кои чернови са отворени — без промени в командите) |

| `state` | състоянието на детайла след действие: `seq`, `snap` (разлика), `result` (обем, стени, болни операции, точно ядро) | вижте 3.3 | 🟡 |
| `session` / `exit` / `crash` / `restore` | старт (версия, ОС), чист изход, срив, възстановяване | | 🟡 |
| Цена | няма пълен проект на действие: само разлики | | 🟡 1000 действия ≈ 0.4 s (`tests/perf.rs`, бюджет 1 s) |

### 3.3 Повторение (replay)

**Решение:** снимките са **разлики в JSON**, не компресирани пълни копия. Детайлът се
сериализира **без тялото** (то е кеш на операциите и се строи отново), и се пише само
разликата спрямо предишната снимка: непроменена операция или скица струва няколко байта
(`{"s":3}`), сменена стойност — пътят до нея. Всяка 25-та снимка е пълна (`{"v":…}`), за да
не се губи всичко при повреден ред. Снимка над 8 MB или дневник над 256 MB → `snap_skipped`
(повторението спира там до следващата пълна снимка). Записва се само активният детайл.

| Опция | Поведение | Ограничения | При нас |
|---|---|---|---|
| `diagnostics::replay::replay(path)` | прилага разликите ред по ред, регенерира след всяка и сравнява с `result` | обем с отн. точност 1e-6, брой стени, болни операции | 🟡 тест `a_recorded_session_replays_to_the_same_volume` (кутия, Extrude, Fillet, Shell) |
| Първа разлика | `first_difference(&steps)`: първата стъпка, която не се повтаря (или не може да се приложи) | | 🟡 тест `a_step_that_does_not_reproduce_is_reported` |
| Повреден / прекъснат ред | последният прекъснат ред (срив) се пропуска; повреден в средата е грешка на стъпка | | 🟡 тест `damaged_and_cut_off_lines` |
| Детайлът на стъпка N | `part_at(path, N)`; `cargo run --example replay -- J --part N out.3dcadcraft` | | 🟡 |
| CLI | `cargo run --example replay -- path` печата всяка стъпка и маркира първата разлика (код 1) | | 🟡 `examples/replay.rs` |
| Кеш на регенерацията | стъпките делят `BuildCache`, както в сесията | | 🟡 |

### 3.4 Автозапис и Restore

| Опция | Поведение | Ограничения | При нас |
|---|---|---|---|
| Кога | на всеки 5 минути и след успешен OK на операция, ако от последния автозапис са минали поне 30 s | само ако проектът има незаписани промени **и** е сменен след последния автозапис | 🟡 `recovery::Autosaver`, тест `autosave_only_when_dirty_and_keeps_three` |
| Никога по време на команда | не се записва, докато е отворен диалог на операция (преглед), влачене или Edit Feature (rollback) | | 🟡 `gui/diag.rs::diag_busy` |
| Къде | `<root>/recovery/<проект>-<хеш>-<време>.3dcadcraft` + `<файл>.json` (оригиналният път, време, сесия, вид) | хешът е от пътя (или от id на проекта, ако не е записван) | 🟡 атомарно (`Project::save` + `write_atomic`), във фонова нишка с копие на проекта |
| Колко | последните 3 на проект | | 🟡 `recovery::prune` |
| Файлът на потребителя | **никога** не се презаписва автоматично | | 🟡 |
| Чист изход | при нормално затваряне описанието на сесията (`session-….json`) получава `clean_exit: true` | срив / убит процес оставят `false` | 🟡 `diagnostics::finish` в `main.rs` |
| Предложение при старт | ако предишната сесия не е затворена чисто и неин автозапис е по-нов от оригиналния файл (или проектът не е записван / файлът липсва): прозорец **Restore** — „Restore the autosaved version of …?“ с **Restore** / **Open Original** / **Discard** | предлагат се само автозаписите на предишната сесия; два отворени екземпляра на програмата не се различават | 🟡 `recovery::offers`, тест `restore_is_offered_only_after_an_unclean_exit_for_newer_autosaves`; чака визуална проверка |
| Restore | отваря автозаписа; пътят става оригиналният, проектът е „незаписан“ (`*`), записът е по избор на потребителя | | 🟡 `restore_autosave`; чака визуална проверка |
| Open Original | отваря оригиналния файл; автозаписите остават (изтриват се с ротацията) | сиво, ако оригиналът липсва | 🟡 |
| Discard | изтрива автозаписите на проекта от тази сесия | | 🟡 тест `discard_deletes_the_files` |

### 3.5 Доклад за срив

| Опция | Поведение | Ограничения | При нас |
|---|---|---|---|
| Кука | `std::panic::set_hook` се слага в `main.rs` преди eframe (`diagnostics::start`) | предишната кука остава (печата паниката) | 🟡 `crash::install_hook` |
| Файл | `<root>/logs/crash-YYYYMMDD-HHMMSS.txt`: съобщение, място, нишка, сесия, backtrace (`force_capture`), последните 200 реда от лога и последните 50 от дневника | | 🟡 тест `crash_report_content` (с измислена паника, без истинска) |
| Аварийно копие | записва автозапис (`kind: emergency`) на последното **съгласувано** състояние: копие на проекта, взето след последното действие (не състоянието по средата на кадъра) | `try_lock`, без чакане; `catch_unwind` около записа | 🟡 тест `handle_writes_report_and_emergency_autosave` |
| Очаквани паники | паниките, хванати от защитата на ядрото (`crash::guard` в `kernel::exact`), са само ред в лога — те вече стават грешки на операцията | | 🟡 тест `guarded_panics_are_caught` |

## 4. Поведение в дървото и при редакция

Няма нищо в дървото на модела. Дневникът записва Edit Feature като `command_start` /
`command_ok` на командата и снимка след OK. По време на Edit Feature (rollback) не се правят
снимки и автозапис.

## 5. Крайни случаи и грешки

- Няма папка на данните (няма `APPDATA`/`HOME`): лог само в stderr, без дневник и автозапис.
- Файлът на лога / дневника не може да се отвори: предупреждение в stderr, програмата работи.
- Автозаписът не успява: ред `autosave failed: …` в лога; следващият опит е по графика.
- Паника по време на запис в лога: куката не чака заключването (`try_lock`).
- Паника вътре в куката води до abort (правило на Rust) — затова кодът ѝ не съдържа `unwrap`/`panic`.

## 6. Реализация

- `src/diagnostics/mod.rs` — `root`, `start`/`finish`, `open_session`, `rotate`, `write_atomic`, време (UTC без външни библиотеки), стабилен хеш (FNV-1a).
- `log.rs` — логерът; `journal.rs` — дневникът, `diff`/`apply`, `Outcome`; `replay.rs`; `recovery.rs`; `crash.rs`; `bundle.rs`.
- `src/gui/diag.rs` — куките в GUI (един метод на кадър `diag_frame`), прозорецът Restore, менюто Help; `gui/files.rs` — `DialogPurpose::Diagnostics`.
- `main.rs` — `diagnostics::start` преди eframe, `diagnostics::finish` след затваряне.
- Други куки: време на операция над 200 ms (`part::build_features`), запис/отваряне (`document::format`), износ (`part::export`), предупреждения на presets.
