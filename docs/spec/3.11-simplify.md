# 3.11 Simplify (assembly)

Status: ✅ done · 🟡 partial · ⬜ to do · ⛔ waiting for another feature.

## 1. Purpose

An assembly becomes one lightweight part: for a customer or supplier without the design's
details, for a layout, for a faster top-level assembly. Inventor's **Simplify** (Assemble ›
Simplification) leaves components out, removes features, replaces components by envelopes and
writes one part file (or a Substitute model state) that stays linked to the assembly.

Ours makes a **part of the design file** that derives the assembly's parts where they stand
(Derive Assembly, spec 3.10 §3.5) with the simplification in its link: it follows the assembly
on Update (a component moved, a part changed) and keeps its faces' names where the geometry
stays.

## 2. Inputs

- **Assemble › Simplification › Simplify** (alias `SIM`), a panel with six tabs.
- Components to leave out are picked in the view or the browser.

## 4. Browser and editing

- The new part's base feature is a derived import named after the assembly (Edit opens Derive:
  style, scale, mirror; the simplification options are kept). Break Link keeps the geometry.

## 5. Edge cases and errors

- Every component left out: `Simplify: every component is left out`; nothing is made.
- A part of a linked file that cannot be read: `Simplify: the model cannot be read`.
- Parts not built by the exact kernel cannot be derived (spec 3.10 §3.5).

## 6. Implementation

- `part::simplify::simplify_assembly` (per part feature rules, exclusions, internal parts, voids,
  envelopes), called by `DeriveLink::bodies` when the link has a `simplify` and the source is an
  assembly (`DeriveSource::paths`: each part's occurrence path).
- `assembly::make::make_simplified` / `simplified_part`; GUI `gui/simplify.rs::asm_simplify_ok`.
- Tests: `tests/simplify.rs` (exclusion by size and by component, envelopes, single solid,
  internal parts, voids, Update after a component moves).
