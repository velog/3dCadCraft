# 0.5 Parameters and expressions (Manage → Parameters, fx)

Status: ✅ done · 🟡 partial · ⬜ to do · ⛔ waiting for another feature.

## 1. Purpose

Every size is a named **parameter**. Its value can be a number or an **expression** that uses other parameters: `d1 = d0 / 2`, `wall = 3 mm`, `L = 2 * wall + 40`. Changing one parameter updates everything that depends on it. This way the part becomes a "family" driven by a few numbers.

## 2. Kinds of parameters

| Kind | Inventor | Status |
|---|---|---|
| **Model parameters** | created automatically from every dimension in a sketch and every value of a feature (Extrude distance, Revolve angle…): `d0`, `d1`, … They can be renamed | ✅ sketch dimensions; 🟡 Extrude values (in the table; ⬜ expression in the Extrude dialog) |
| **User parameters** | created by the user (Add Numeric) with a name, expression, unit, comment | ✅ |
| Text / True-False parameters | text and logical parameters (for rules) | ⬜ (7.5) |
| Linked / Derived | parameters from an external file | ⬜ |

## 4. Expressions

| Behaviour | Status |
|---|---|
| Numbers, `+ - * / ^`, parentheses, unary minus | ✅ |
| Parameter names | ✅ |
| Functions: `sin cos tan asin acos atan sqrt abs floor ceil round min max`, constant `PI` | ✅; 🟡 also `sinh cosh tanh asinh acosh atanh exp ln log sign pow(x, y)` and `E` (test) |
| **Units and kinds in equations**: any unit after a value (`5 N / 2 mm`, `2 kg * 9.81 m/s^2`, `100 km/h`, `10 mm^2`, `20 degC`), a unit alone is one of it (`m/s^2`); kinds are checked and converted: `Force / Length` into N/m converts from N/mm, into a length it is "the result is a force per length (stiffness), the parameter is a length"; sums need one kind (a bare number takes the parameter's unit); powers of quantities whole; trig of angles or ratios; `sqrt` halves the powers; a unitless parameter takes any value (as before) | 🟡 test `dim_tests::quantities_in_equations`; parameter names win over unit names (a parameter `t` stays a parameter; after a number `5 t` is tonnes); waiting for a visual check |
| **Physical properties as parameters** (our addition: Inventor reads them only through iLogic) | — | 🟡 read-only rows `PartMass` (kg), `PartVolume` (mm³), `PartArea` (mm²), `PartCogX/Y/Z` (mm), measured with the materials' densities after each rebuild (`update_physical`, only when an equation uses them or the table is open); usable in user parameters (`Weight = PartMass * 9.81 m/s^2` → N); a size that depends on one, directly or through others, is refused: "a size cannot depend on PartVolume (it would change it)"; test `physical_properties_in_equations`; waiting for a visual check |
| Units in the expression: `10 mm`, `1 in`, `0.5 cm`, `45 deg`, `1 rad`; no unit → the parameter's unit | ✅ (bare numbers in a sum with a quantity get the parameter's unit; in an argument of sin/cos — degrees); 🟡 the Dynamic Input fields next to the cursor take equations and parameter names too (`10+5`, `d0*2`, `1 in`: letters after a first digit belong to the field) — waiting for a visual check |
| Angles are entered in degrees and stored in radians internally | ✅ |
| Circular dependencies are refused with a clear message | ✅ |
| The expression is kept; the value is recomputed on every change | ✅ |

## 6. Implementation

`part/params.rs`: `Parameters` (table), `Expr` (parsing and evaluation), `ParamValue`. The part keeps the table. On regeneration the parameters are evaluated first, then their values are written into the sketch dimensions and the features.
