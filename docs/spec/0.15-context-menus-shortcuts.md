# 0.15 Right-click, keys, mouse and conveniences

Status: ✅ done (visually checked) · 🟡 partial (what is missing is stated) · ⬜ to do · ⛔ blocked (by what is stated).

This specification collects the **right-click behaviour** for every kind of selected object and
every place (view, browser, sketch, command), the **keys and command aliases**, the
**mouse** and the **conveniences** that Inventor 2027 gives the user. The statuses were
checked against the code as of 2026-10-20 (`src/gui/*.rs`) and against [REFERENCE.md](../REFERENCE.md).

**Boundary with other work:** the selection filters, the **Select** menu on Shift+right-click and
the picking priorities are in [0.9-selection.md](0.9-selection.md) (done separately, in
`gui/select.rs`). Here they are only mentioned. The marking menu and the context menus use
the same selection objects (`SelItem`), but do not change them.

Notation in the tables: **[H]** — confirmed in Inventor Help; **[S]** — secondary
source (book, blog, forum); **(?)** — unconfirmed, to be checked in real Inventor
before the row becomes ✅. Where Inventor is not documented, the row says **our choice**.

---

## 1. Purpose

The owner wants that, whatever is selected — a sketch, a feature, a face, an edge, a dimension —
the right button gives **exactly the commands that make sense for that object**, as in
Inventor, together with all the "small" conveniences an Inventor user is used to: repeating
a command, keyboard aliases, command search, Look At, Isolate, visibility by
object kind, a hint next to the cursor, etc.

Goals:
1. An Inventor user finds the same command **in the same place in the menu** and with the
   same name.
2. Nothing in the menu is "dead": an unavailable item is grey and says why (0-ui §4).
3. Everything done with a right-click also has another path (ribbon, key, Properties).

## 2. Inputs

- **Where the right-click happens:** the view (idle 3D, sketch, open command), the browser, the ViewCube,
  the ribbon/panels.
- **The object under the cursor** and **the current selection** (`SelItem`: Face / Edge / Feature / Body /
  Sketch; in a sketch — curve, point, constraint, dimension, projected geometry).
- **The environment:** part, sketch; later assembly and drawing (rule 8 — the menus are described
  as an "environment × object kind → items" table, so assemblies can be added without a rewrite).
- **The active command** (sketch tool, dialog with selectors, Extrude/Revolve…).
- **The last command** (for Repeat) and the list of recent commands.

**Alias input rules** (our exact behaviour):

1. **When input starts.** A pressed letter (A–Z, without Ctrl/Alt; Shift is allowed) or
   one of the characters `]` `/` `;` `=`, when: the cursor is over the view or over the browser, no
   text field has focus, no modal window is open, and Dynamic Input is **not** active
   (it takes the digits, `.` `,` `-`). A letter during Dynamic Input also starts
   input (the HUD does not accept letters).
2. **Without the field** (`alias_input = false`, default): the buffer is shown in the status
   bar to the right of the prompt, e.g. `Command: LO_ → Loft`.
   - If the buffer is **exactly** an alias in the current environment and there is **no longer** alias
     starting with it → the command starts **at once** (so E, R, S, H, L, C, D, X, O
     stay instant, as today).
   - If it is exact but longer ones exist (e.g. `S` and `S3`, `SH`, `SW`, `SP`): it waits up to
     `alias_timeout_ms` (a field in `AppOptions`, default 600 ms) for a further letter;
     Space/Enter starts the exact one at once; after the timeout — the exact one.
   - If there are several matches and no exact one: Tab / ↓ — next, Shift+Tab / ↑ —
     previous, Space/Enter — starts the one shown.
   - Invalid buffer → red text "`QQ` — no such command here", nothing starts;
     Backspace removes the last letter; Esc clears the buffer (it does **not** abort the command — by
     our rule Esc works layer by layer; deviation from Inventor).
   - The buffer is cleared after 2 s without a key press, on a click in the view and when the environment changes.
3. **With the field** (`alias_input = true`): the first letter opens a field next to the cursor (16 px
   right-up), holding the letter; **nothing starts by itself** — Space, Enter or right-click
   is needed (as in Inventor). The list (if `alias_autocomplete`) is below the field, up to 8 rows:
   icon · name · alias/key · grey "Tab › Panel". Tab / ↓ / ↑ move the highlighted row;
   a click starts the row; ← → and Backspace edit anywhere in the field. Esc or a click outside
   the field closes it **and resumes** the paused command (deviation: Inventor aborts it).
   Starting a command aborts the current one, like every command start (0-ui §3.1).
   While the field is open, the sketch tool is paused (it takes no clicks).
4. **Matching** (shared with the search §5.3, a module from G0): result order —
   (a) exact alias; (b) **recent commands** (up to 10, kept in `settings.json`
   `recent_commands`) that match; (c) an alias starting with the buffer; (d) a name with a
   word starting with the buffer ("ext" → Extrude, Extend); (e) with autocomplete — substring and
   fuzzy match (see §5.3). Commands that are **not for this environment** are not shown
   (Hole in a sketch → invalid). Unfinished ones (grey in the ribbon) are shown at the bottom, grey, with
   the FEATURES section, and cannot be started.
5. **Conflicts:** Shift+letter is an alias (as in Inventor), but it does not interfere with Shift in Trim/
   Extend (there it is held, not pressed on its own). F-keys, Ctrl+…, Alt+… never
   go into the buffer.

## 7. Browser and editing behaviour

- Commands from the menus go through **the same** `Action`s as the ribbon and the keys (one
  command registry — group G0), so they have the same names, icons, reasons for being
  unavailable and Undo. 🟡 The registry is `gui/commands.rs` (`COMMANDS`, `by_id`, `by_action`);
  the ribbon, Repeat and F1 for the sketch tools read from it.
- Every change from a menu makes a `checkpoint` (rule 4); on failure nothing changes
  (rule 5).
- The menus are an "environment × object kind → items" table (data, not code in every place), so
  that assemblies can be added (rule 8) and the marking menu can use the same items.

## 8. Edge cases and errors

- Right-click on an object that is not selected while there is a selection of another kind: the selection is
  replaced by the object (our choice), unless Shift/Ctrl is held.
- Right-click during dragging/navigation: ignored.
- An item that cannot be run (for example Edit Feature below EOP): grey, with the reason in
  the tooltip.
- Alias of a command from another environment: red "<buffer> — not available in a sketch".
- Alt+S with a modal window open: nothing.
- A failing command from a menu: `<Command>: <reason>` in the status bar.
