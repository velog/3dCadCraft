# 0.6b Many documents in one file, and separate files

## 1. Purpose

The owner's choice (2026-10-27): **the work is kept in one file**. A `.3dcadcraft` file is a
*design file* holding every document of a design: parts, sheet metal parts, assemblies, drawings and
later presentations. The ribbon creates new documents **inside the open file**, and
the user works across them in one session: an assembly places the file's parts, and a drawing shows them.
**Separate files** stay possible: any document can be saved to its own file (`.ccpart`, `.ccasm`,
`.ccdrw`, spec [0.6a](0.6a-file-types-projects.md)) and linked back, or brought into the file again.

Inventor stores every document in its own file and has no container; its closest tools are Pack and
Go, Make Components and Create Component. Onshape works the other way: one *document* holds many
tabs (Part Studios, Assemblies, Drawings), and *Move to Document* moves a tab and its references into
another document, leaving a link behind. Ours combines the two:

- the commands, names and environments follow Inventor;
- the storage follows the one-file model;
- a document can switch between being stored inside the file and in a separate file without losing
  its references.

Terms used below:

- **design file**: a `.3dcadcraft` file (the `Project` of `document::`), one or more documents;
- **internal document**: stored inside the open design file (`DocRef { library: None }`);
- **linked document**: stored in another file, reached through a `LibraryLink` (relative path +
  that file's project id) and the document id (`DocRef { library: Some(..) }`);
- **single-document file**: `.ccpart` / `.ccasm` / `.ccdrw` / `.ccpres`, the same container with
  exactly one document (0.6a).

## 2. Inputs

- the open design file and its active document;
- the storage default: the active design project's `new_documents` (§3.6), else Application
  Options → Save;
- for linking or importing: a file chosen in the Open dialog (`.3dcadcraft` or a single-document
  file) and, in a design file with several documents, the documents chosen in it.

## 3. Options and behaviour

### 3.1 The design file

| Option | Inventor behaviour | Ours | Status |

The others are listed in the browser's **Documents** node (§3.4). *Open with options* chooses which documents open in tabs | 🟡 opens the saved document; the Documents node and Open with options are ⬜ |
| Save | saves the active document and asks about changed documents that depend on it | Save writes the whole design file (every internal document) atomically. Changed **linked** documents are listed in a Save dialog with Yes / No per file, as Inventor's dependents list | 🟡 the design file; the dependents dialog is ⬜ |

### 3.2 Ribbon: creating documents inside the file

A **Documents** panel on the **Manage** tab, in every environment: part, sheet metal, assembly and
drawing. The same commands are in the browser's right-click menu on the Documents node, and the
first five are also in the New ▾ list of the Quick Access Toolbar (as *… in This File*). Each command
creates the document from the template of its kind, makes it the active document in a new tab and
records one Undo step of the design file.

| Command | Alias | Inventor counterpart | Ours | Status |
|---|---|---|---|---|
| New Part | `NP` | File → New → Standard.ipt (a new file) | a part from the part template, inside this file; the sketch on XY starts as in New | 🟡 checked by the agent in the app 2026-10-27, waiting for the owner's check (the part becomes active; no automatic sketch yet) |
| New Sheet Metal | `NSM` | File → New → Sheet Metal.ipt | a sheet metal part with the active project's sheet metal rule | 🟡 the default rule (no project rules yet); checked in the code only |
| New Assembly | `NA` | File → New → Standard.iam | an empty assembly inside this file. Place then lists this file's parts first (§3.3) | 🟡 checked by the agent in the app 2026-10-27, waiting for the owner's check (File → New Assembly still makes a new file) |
| New Drawing | `ND` | File → New → Standard.idw | a drawing inside this file; Base View offers this file's parts and assemblies | 🟡 `new_drawing`, now also on Manage › Documents |
| New Presentation | `NPN` | File → New → Standard.ipn | disabled until presentations exist (FEATURES 3.x) | ⛔ presentations |
| Insert Document | `IDF` | — (Pack and Go copies files) | copies documents of another file into this one as internal documents. Their references come along, each document is copied once and ids are remapped (`Resolver::append`) | 🟡 `Resolver::append` exists; the command is ⬜ |
| Link File | `LF` | Place (assemblies), Base View (drawings) | adds a link to another file without placing anything; its documents appear under *Linked Files* (§3.4) for Place and Base View | 🟡 `Resolver::link` exists; the command is ⬜ |
| Duplicate Document | `DUP` | Save Copy As | a copy of the active document in this file, named `<name> Copy`. References to it are not moved | 🟡 checked by the agent in the app 2026-10-27, waiting for the owner's check |
| Rename Document | `RND` | Rename in Vault / Explorer | renames the document (its id stays, so links from other files still resolve) | 🟡 checked by the agent in the app 2026-10-27, waiting for the owner's check (a taken name is refused in the dialog) |
| Delete Document | `DDC` | delete the file in Explorer (breaks references) | removes an internal document that nothing references. A referenced one is refused with the list of the documents using it: `Delete Document: used by Assembly1, Drawing1` | 🟡 checked by the agent in the app 2026-10-27, waiting for the owner's check |
| Documents | `DM` | — | the Documents window: the table of §3.4 with every action of this section and §3.5 | 🟡 checked by the agent in the app 2026-10-27, waiting for the owner's check |

Rule 15 applies: the panel and the Documents window are built first, with every command, icon and
alias; commands without logic yet are disabled, with this row in the tooltip.

### 3.5 Inside ↔ separate

| Option | Inventor behaviour | Ours | Status |
|---|---|---|---|
| Save to Separate File (extract) | — (Onshape: Move to Document) | writes an internal document to `<folder>/<name>.<kind ext>` (the workspace, or the design file's folder) and adds a link to it. Every reference in this file is remapped to the link (`remap_references`), and the internal copy is removed. One Undo step restores the internal copy and the references; the written file stays on disk | ⬜ |
| … with its references | Onshape: *Move all referenced tabs* | an option: an assembly or drawing taken out together with the internal parts it uses, each to its own file. Without it, the new file links back to this design file (`library` link to the container + document id) | ⬜ |
| Embed (make internal), alias `MKI` | Pack and Go copies files into one folder | copies a linked document into this file (`Resolver::append`) and remaps every reference to the copy; the link goes when unused (`prune_libraries`). The other file is not changed | 🟡 `append` + `prune_libraries` exist; the command is ⬜ |
| Embed All (Pack) | Pack and Go | every linked document, recursively, becomes internal; the design file then stands alone (send it by mail) | 🟡 `Resolver::pack` exists; the command is ⬜ |
| Separate All (Unpack) | — | every internal document to its own file in a chosen folder, the design file keeping only links. With an empty design file left, it is offered to replace it by the top assembly (`.ccasm`) | ⬜ |
| Read-only libraries | library files open read-only | a document linked from a project library cannot be embedded silently: Embed asks, as the copy no longer follows the library | ⬜ |
| Identity | file name | a document keeps its `DocumentId` when it moves in or out of a file. So drawings' annotations, assembly constraints and BOM overrides that name it stay valid, and a later Embed of the same file finds the same document | ⬜ |

### 3.6 Default storage

| Option | Inventor behaviour | Ours | Status |
|---|---|---|---|
| Application Options → Save → *New documents* | — | **In one file** (default, owner's choice) or **As separate files**. *In one file*: §3.2 and New add to the open design file. *As separate files*: §3.2 creates an unsaved single-document file in a new tab, linked when it is used (Place, Base View) | ⬜ |
| Per project | — | `DesignProject::new_documents` (`in_file` / `separate`, absent = the Application Options value) overrides it for the project's files | ⬜ |
| Create Component / Make Components | always separate files | their *Store* option starts from this default | ⬜ |

## 4. Browser and editing behaviour

- **Undo** covers the whole design file: creating, renaming, deleting, extracting or embedding a
  document is one step. Files written on disk by Save to Separate File are never deleted by Undo.
- **Kinds stay apart:** a sheet metal part is a part, so it is created by New Sheet Metal, not by a
  document kind of its own.
- **Old files** are not changed by any of this. A `.3dcadcraft` file from an older build opens with
  every document in the Documents node. A single-document file holding several documents opens as a
  design file (0.6a §5).

## 5. Edge cases and errors

- Deleting or extracting the last document of a file is refused: `Delete Document: a file keeps at
  least one document`.
- A cycle (an assembly placing an assembly that places the first) is refused at Place, Insert
  Document and Embed.
- Extract to a file name that exists: asks Replace / Rename / Cancel. Replace refuses a file of
  another kind.
- A linked file changed on disk while open: its documents reload on the next activation, and the
  *Linked Files* row shows *changed on disk* until then.
- A linked file that holds a document with the same id as an internal one (copied by hand): the
  internal one wins, and the link is flagged as a conflict.
- Two tabs of one design file: closing one leaves the file open; *Close* of the file's last tab asks
  Save / Don't Save / Cancel for the whole file.

## 6. Implementation

- Data: nothing new in the document format. `Project` holds the documents. `LibraryLink` /
  `DocRef::library` are the links. `Resolver::{link, append, pack}` and
  `DocumentData::remap_references` are the moves. New: `Project::extract(id, path)` and
  `Project::embed(link, ids)`, with unique names (`Project::free_name(kind)`), cycle checks
  (`Project::would_cycle`) and tests for each row of §3.5 (references remapped, ids kept, Undo
  restores).
- `DesignProject::new_documents` (additive serde field); Application Options → Save.
- GUI:
  - `gui/doc_tabs.rs`: tabs of one design file share `project` / `history` (a tab names a file
    slot + a document id);
  - `gui/documents.rs`: the Documents panel commands, browser nodes and the Documents window;
  - `gui/place.rs`: the *In This File* list;
  - `gui/commands.rs`: entries with the aliases of §3.2 on Manage › Documents.
- Order: D1 interface (panel, window, browser nodes, disabled commands) → D2 New … in this file +
  shared tabs → D3 Extract / Embed / Pack / Unpack → D4 Create Component / Make Components
  (after derived parts).
- Done 2026-10-27: `document/documents.rs` (`free_name`, `add_new_document`, `users_of`,
  `duplicate_document`, `rename_document`, `delete_document`, tests), `gui/documents.rs` (`DocCmd`,
  `DocsUi`, the Documents window, Rename dialog, browser menus), Manage › Documents / Storage panels
  (`Envs::DOCUMENTS`: part, assembly, drawing, not inside a sketch), Place's *In This File* list. The
  aliases avoid E / H / L / D / O / X starts that must fire at once (Embed is `MKI`, not `EMB`).
