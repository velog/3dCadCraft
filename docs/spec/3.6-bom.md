# 3.6 Bill of Materials (BOM)

Status: ✅ done · 🟡 partial · ⬜ to do · ⛔ blocked by another feature.

## 1. Purpose

The list of what an assembly is made of: every component once per row with its quantity, part number,
description and the other Properties, numbered (Item). It feeds parts lists on drawings and exports
for purchasing / ERP. Second step of the owner's schedule of 2026-10-24 (after joints).

## 2. Inputs

- The assembly's occurrences and their components (parts of the file, linked part files).
- Each component document's Properties (`docs/spec/0.16-iproperties.md`) and its **BOM Structure**.
- Per occurrence: a BOM Structure override (Reference), visibility does not matter.

## 4. Browser and editing behaviour

- Changing BOM Structure or an Property is an Undo step of the assembly's file (components of the file).
- The BOM is computed from the current assembly every time the window draws (nothing stored except the
  BOM Structure, overrides and later item overrides).

## 5. Edge cases and errors

- A component whose part file is missing: a row "(missing) …" with its quantity, so nothing is lost silently.
- Two different documents with one part number: one row when merging (Inventor warns); our row lists both.

## 6. Implementation

- `document::iprops::BomStructure` on `IProperties::bom_structure` (default Normal, skipped); per occurrence
  `Occurrence::bom` (an override, skipped when `None`).
- `assembly::bom`: `rows(asm, view, merge, info)` → `Vec<BomRow>` with a GUI-free `info(DocRef)` callback
  (file name, Properties, material); `to_csv`.
- GUI `gui/bom.rs`: the window, tabs, table, BOM Structure per row, Export; `gui/bom_thumbs.rs`: the Thumbnail column's pictures (`part::thumbnail`, cached by `DocRef` and the component's signature, compared once a second).
