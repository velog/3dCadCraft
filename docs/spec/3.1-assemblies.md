# 3.1–3.3 Assemblies: placing components, constraints, joints

Status: ✅ done · 🟡 partial · ⬜ to do · ⛔ blocked by another feature.

> **Research status.** This first version is written from the behaviour of Inventor's assembly
> environment as commonly documented, and from SolidCraft's implementation (see §6). Before a
> row is implemented, check it against the Inventor 2027 help (topics listed in §7) and correct
> the row; note the GUID in §7.

## 1. Purpose

An assembly places parts and subassemblies (components) in one space and relates them with
**constraints** (Inventor's Mate, Flush, Angle, Tangent, Insert, Symmetry) or **joints** (Rigid,
Rotational, Slider, Cylindrical, Planar, Ball). The relations fix the components' positions
and leave the remaining degrees of freedom free, so the user can drag a mechanism.

## 2. Inputs

- Components: part (`PartDocument`) and assembly documents of the project, or linked from a
  library (Link / Append, `docs/FILE_FORMAT.md`).
- Geometry for relations: faces, edges, vertices, work features and origin geometry of an
  *occurrence*, referenced as **(occurrence path, persistent name)** (CLAUDE.md rule 8).

### 3.2 Constraints

Each constraint is a set of equations between two occurrences' geometry (§6.2). Offset and
angle values accept expressions and parameters (rule 12).

| Constraint | Inventor behaviour | Restrictions | Our status |
|---|---|---|---|
| **Mate** (plane–plane) | the planes coincide, normals opposite; Offset along the normal | | 🟡 normals opposed, the offset along the first face's outward normal (`relation::residuals`); test `mate_leaves_three_freedoms_and_three_mates_none` |
| **Mate** (axis–axis, point–point, line–plane, point–plane) | the axes / points coincide, the line lies in the plane… | | 🟡 axis–axis (cylinders, cones, straight edges, circles' axes), circle centre–plane, axis–plane; point–point ⬜ (no vertex picking yet) |
| **Flush** | planes coincide (or at an offset) with normals in the same direction | planes only | 🟡 Mate's Flush solution: normals the same way, the offset along the first normal |
| **Angle** (Directed / Undirected / Explicit Reference Vector) | angle between two faces or edges | | 🟡 Undirected only (`n_a·n_b = cos θ`; at 0° / 180° the equation has a double root: use Mate / Flush there); Directed and Explicit Reference Vector ⬜ |
| **Tangent** (Inside / Outside) | a cylinder, cone or sphere touches a plane or another such face | | ⬜ |
| **Insert** (Opposed / Aligned) | the axes of two circular edges coincide and their planes mate (or flush) at an offset — a bolt in a hole; leaves the rotation free | circular edges | 🟡 two circular edges: their planes' normals opposed (Opposed) or the same way (Aligned) and the second centre at the offset along the first normal; the turn about the axis stays free; Lock Rotation ⬜ |
| **Symmetry** | two components mirror each other about a plane | | ⬜ |
| Limits (Minimum / Maximum / Resting) | a range for an offset or angle; the solver stays inside it while dragging | | ⬜ |
| Name, Suppress, Edit, Delete | in the browser under both occurrences | | 🟡 `Mate:1`…; Relationships folder of the browser (double-click / Edit reopens the panel, Suppress, Delete); Properties edit the offset in place |
| Preview and the solution flip | the second component moves live; Mate/Flush flips | | 🟡 Show Preview solves with the draft and draws the moved components; Predict Offset and Orientation picks Mate / Flush from the normals and measures the offset while no value was typed |
| Motion (Rotation, Rotation–Translation) and Transitional constraints | gear ratio; cam follower | | ⬜ later (3.4) |
| Degrees of freedom display | per occurrence, glyph of the free translations and rotations | | 🟡 the number in the occurrence's Properties (rank of its block, the others held); the glyph ⬜ |
| Origin and work geometry | constraints to a component's origin planes / axes / centre point, its work planes, axes and points, and the assembly's own origin | picked in the browser (they are not drawn in the view) | 🟡 `GeomRef::Origin` / `Work`; occurrence 0 is the assembly's origin, which never moves |
| Offset 0 or the current distance | Predict Offset uses the current distance | | 🟡 checkbox *Use the current distance*, remembered (owner, 2026-10-24); off: offset 0; the orientation (Mate / Flush) is still predicted; an angle is always measured |
| Over-constrained / conflicting | the conflicting constraint is marked sick, the rest still solve | rule 5 | 🟡 a new or edited constraint that does not solve is refused and changes nothing; consistent redundant ones are accepted; a constraint whose face / edge is gone is sick (red in the browser, the reason in its tooltip) and skipped |

### 3.3 Joints

A joint is a predefined set of constraints between two **joint origins** plus named values (the
motion) with optional limits.

| Joint | Values (motion) | Our status |
|---|---|---|
| **Rigid** | none | 🟡 origins together, z opposed (Flip: the same way), x along x |
| **Rotational** | angle | 🟡 free, or locked at a value; limits |
| **Slider** | distance | 🟡 slides along the first origin's z, no turn; locked / limits |
| **Cylindrical** | angle, distance | 🟡 turn and slide free; the distance can be locked or limited (the angle ⬜) |
| **Planar** | x, y, angle | 🟡 free in the plane of the first origin (values ⬜) |
| **Ball** | three angles | 🟡 free (values ⬜) |
| Joint origins (snap: centre of a planar face, centre of a circular edge or cylinder end, a vertex, a work point; with offset and flip) | — | 🟡 face centre (area-weighted) + normal, circle centre + outward normal, axis, origin / work geometry from the browser; drawn as a triad while picking; Flip; vertices and origin offsets ⬜ |
| Limits, Start / current value, Animate (drive the value) | — | 🟡 Minimum / Maximum: a value past a limit is held there and solved again (drags stop at it); Start value and Animate ⬜ (A4) |
| Automatic joint type from the picked geometry | — | ⬜ (Rotational is the default) |

## 4. Browser and editing behaviour

- Occurrences are listed in the assembly browser; their relations are nested under each
  occurrence ("Relationships" folder), a sick one marked as in the part browser.
- Editing a constraint re-solves; a failing edit leaves the previous solution (rule 5).
- Editing a part regenerates the part once; every occurrence shows the new body, relations
  re-find their geometry by persistent name; a missing face makes the relation sick (rule 8).

## 5. Edge cases and errors

- Geometry deleted in the part → the relation is sick, the occurrence keeps its last position.
- Conflicting constraints → the newest is refused with its reason ("Assembly constraint: …").
- Redundant constraints are allowed when they agree (Inventor accepts consistent
  over-constraints); they are detected by the rank analysis and reported, not an error.
- A loop of joints/constraints (four-bar linkage) must solve — unlike SolidCraft's tree walk.

## 6. Implementation

### 6.1 Data model (`document` + new `assembly`)

- `AssemblyDocument { occurrences, relations, params }`, in `Project` next to parts.
- `Occurrence { id, name, component: DocRef, transform (rigid), grounded, visible, colour? }`
  (exists partly in the format). Occurrence paths `[id, id, …]` for subassemblies.
- `GeomRef { path: Vec<OccurrenceId>, name: String, hint: Point3 }` — persistent names only.
- `Relation::Constraint { kind, a: GeomRef, b: GeomRef, offset/angle (expression), limits,
  solution }` and `Relation::Joint { kind, a: JointOrigin, b: JointOrigin, values, limits }`.
- Format: new document type and enums → a `FORMAT_REVISION` bump with fixtures.

### 6.2 Solver (shared by constraints and joints)

- Unknowns: 6 per non-grounded occurrence — translation + a small rotation vector applied to the
  current orientation (re-linearised each iteration, so no gimbal lock).
- Every constraint is a few scalar residuals on geometry *transformed into the world*:
  Mate plane–plane = normal·(pB − pA) − offset, nA + nB = 0 (2 independent); axis–axis = the
  direction cross product and the point-to-line distance; Insert = axis–axis + plane offset;
  Angle = (nA·nB) − cos θ; Tangent = the distance from the axis/centre to the plane − r.
- Joints are **the same residuals**: Rigid = coincident frames (6), Rotational = coincident
  origins + aligned z (5), Slider = aligned frames minus one translation (5), Cylindrical (4),
  Planar (3), Ball (3); the joint's values become one more driven residual each when set.
- The same sparse Levenberg solver and rank analysis as the sketch (`sketch::solver`): DOF per
  occurrence, redundant vs conflicting equations, min-norm motion while dragging.

### 6.3 What we take from SolidCraft (MIT OR Apache-2.0, rows in `ATTRIBUTION.md`)

- Joint frame algebra (`crates/doc/src/joints.rs`): `T_B = T_A · F_a · M(q) · Flip · F_b⁻¹`, the
  joint kinds and their value lists, limits clamping.
- **Snap origins** (`Snap::FaceCenter`, `CircleCenter`, `Point`, `Frame`), re-found by
  persistent face name on every solve — exactly our joint origins.
- Occurrence transforms and `world_bodies` (`crates/doc/src/assembly.rs`), the 4×4 helpers,
  URDF export (`crates/io/src/urdf.rs`).
- **Not taken:** its placement solver — it walks the joint graph from grounded occurrences and
  only *checks* closed loops; Inventor solves loops and partially constrained components, so
  joints feed our simultaneous solver instead.

### 6.4 Display and picking

- One mesh per part document, drawn once per occurrence with its transform (instancing).
- Picking transforms the eye ray into the occurrence's local frame (`BRep::pick_face` takes a
  local ray, rule 8); the pick result is (occurrence path, face).

### 6.4a A2 as built (2026-10-23)

- `assembly::relation`: `GeomRef` (face by persistent name + hint, edge by `EdgeRef`), `Geom` (plane with
  its outward normal, axis, circle with the outward normal of its planar face), `resolve_local`,
  `residuals`, `predict`. `assembly::solve`: 6 unknowns per free component (translation + a small turn
  about its own origin, scaled by 50 mm), finite-difference Jacobian, minimum-norm Levenberg steps,
  column weights for a dragged component, degrees of freedom from the rank of each block.
- GUI `gui/constrain.rs`: the panel, picking (edges within 7 px win over the face, hidden edges skipped),
  preview, Relationships, Properties; every change goes through `asm_try` (solve a copy, then commit).
  Free Move / Free Rotate re-solve each frame with the dragged component held (others follow, it snaps
  back along fixed directions). Perf: 30 cubes / 87 constraints 185 ms (`tests/perf.rs`).
