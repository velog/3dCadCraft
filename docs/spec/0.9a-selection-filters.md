# 0.9a One selection model: "everything" + filters, priority and the Shift + right-button menu

Status: ✅ done · 🟡 partial · ⬜ to do · ⛔ waiting for another feature.

🟡 here means: implemented and tested (`command::selection`), waiting for a visual check in
the app (the X11 scripts in `tools/` do not run on Windows).

Complements [0.9-selection.md](0.9-selection.md) (object kinds, Select Other, multiple
selection, context suggestions). This file describes **what** can be picked and how the
user's wishes (filters, priority) combine with what the open command is waiting for.

## 1. Purpose

Until now every mode and every command had its own logic for "what can be picked": in
Faces and Edges mode sketches and work features could not be selected, in Sketch Features
mode only sketches, and the commands checked the kinds one by one. The goal:
- by default **everything can be picked** (faces, edges, vertices, sketches, work
  features, Origin);
- the user **turns off** kinds with filters (check boxes) and chooses a **priority** —
  whether a click on a face selects the face, its feature or its body (Inventor: Select
  Priority);
- inside a command the **intersection** is picked: the kinds the active selector accepts
  (`PickKind`) ∩ the user's filter;
- **Shift + right button** opens a menu with the selection tools next to the cursor (as in
  Inventor).

## 2. Inputs

- filter: a set of categories (see §3), saved in `settings.json` → `options`;
- priority (Select Priority), box (by direction / always Window / always Crossing),
  Enable Prehighlight — also saved;
- the active selector of the open command (`command::flow::Selector::accepts`) or the
  kinds that a command without `Flow` accepts;
- the cursor position (candidates under it, Select Other).

## 4. Priority (Inventor: Select Priority in the Select drop-down)

| Priority | Inventor | A click on a face/edge/vertex selects | Status |
|---|---|---|---|
| **Faces and Edges** (default) | Select Faces and Edges | the object itself; sketches and work features can be selected too | 🟡 |
| **Features** | Select Features (Feature Priority) | the feature that created it (if Features is on; otherwise the object itself) | 🟡 |
| **Bodies** | Select Bodies | the body (Solid Bodies / Surface Bodies) | 🟡 |
| **Sketch Features** | Select Sketch Features | the sketch under the cursor wins over faces and edges | 🟡 |

| Picking order (the same everywhere) | Status |
|---|---|
| work point > vertex > work axis > sketch curve/point > edge > face > work plane > Origin (with Sketch Features: the sketch first) — an extension of [0-ui §3.2](0-ui.md) | 🟡 |
| Select Other walks the candidates of **all** enabled categories in the same order, with every priority (until now — only in Faces and Edges) | 🟡 |
| Prehighlight shows only what passes both filters (command ∩ user) | 🟡 |

## 5. Filters in a command

| Rule | Behaviour | Status |
|---|---|---|
| Intersection | only the kind that the active selector accepts **and** that is enabled in the filter can be picked | 🟡 |
| Empty intersection | if the filter turns off everything the selector accepts, the command does not "trap" the user: the selector's kinds apply, and the status bar says "Selection filter ignored: this input takes …" | 🟡 |
| Priority does not apply in a command | the command itself decides what its input is (face, edge…) | 🟡 |
| Commands without `Flow` (Fillet, Hole, Thread, Pattern, Work Feature, Extrude, Start Sketch, Project Geometry) | their kinds are described in one place (`active_pick_kinds`) | 🟡 |

### 6b. Selection in an assembly (Inventor's list, Help 2026)

| Item | Behaviour | Status |
|---|---|---|
| Component, Part, Feature Priority, Select Faces and Edges | as in §6a | 🟡 |
| **Select Bodies** | a body of a part; the whole body lights up. Our addition to Inventor's assembly list (owner, 2026-11-02): parts can hold several | 🟡 |
| **Points** in Select Faces and Edges | a vertex within the point snap of the cursor, on the part under it, before edges and faces; a dot in the view | 🟡 |
| **Measure between points** | Measure in an assembly takes vertices before edges and faces: two points on any components give their distance and ΔX, ΔY, ΔZ (owner, 2026-11-02) | 🟡 |
| **Measure: middles and centres** | Measure in a part and an assembly also snaps to the middle of a straight or free-form edge and the centre of a circle or arc, named next to the point while hovering; 8 px, so the edge stays easy to pick; a hole's centre works with nothing under the cursor. An arc's own middle ⬜ | 🟡 |
| **Measure along the axes** | in a part and an assembly the view shows the shortest line (orange) and the way along X, Y and Z with each leg's length, in the triad's colours (red, green, blue); the window's dX, dY, dZ use the same colours; a leg of no length is not drawn (owner, 2026-11-02) | 🟡 |
| Select Visible Only | the modes below skip hidden components; on by default | 🟡 |
| External Components (shown) | what can be seen from outside: rays from the six sides of the assembly's box, on a worker thread; a component counts when at least *Percent* of the rays reaching its box hit it first. Inventor's page does not say how it decides | 🟡 |
| Internal Components (hidden) | the inverse of External | 🟡 |
| Component Size | At Least / At Most a size (the box's diagonal), in mm or as a share of the largest (100 % = the largest) | 🟡 |
| Component Offset | inside a box around the selection (none: the assembly) grown by Offset; Include Partially Contained. Dragging the box ⬜ | 🟡 |
| Sphere Offset | the same with a sphere round it. Dragging the sphere ⬜ | 🟡 |
| Select by Plane | wholly on one side of an origin-parallel plane; Flip. Any plane ⬜ | 🟡 |
| All in Camera | at least *Percent* of the box's screen rectangle in the view | 🟡 |
| Invert Selection, Previous Selection | one previous set is remembered | 🟡 |
| Compact Selection Set | ⬜ | ⬜ |

All values change the selection live; OK keeps it, Cancel brings back the old one.

## 10. Edge cases

- every category is filtered out → nothing lights up, the box selects nothing, Select All
  selects nothing; the "Select All Filters" button is in the menu;
- a selection already made is not removed when the filter changes (Inventor does the same);
  changing the priority clears the selection (the kind of the items changes);
- vertices without a persistent name are not offered (rule 2).

## 11. Implementation

- `command::selection` (no GUI, with tests): `Category`, `Filter` (bit mask, saved as the
  list of the excluded ones), `Priority`, `BoxMode`, `kinds_filter(&[PickKind])`,
  `effective(selector, user)` → `Effective { filter, overridden }`, `resolve(raw,
  priority, filter, surface)`, `rank`, `filter_candidates`, `box_takes`, `shift_menu(ctx)`;
  tests: intersection (8 combinations), priority, order and Select Other across mixed kinds,
  box, menu content by context, saving; `tests/perf.rs`: 10k candidates.
- `gui/select.rs`: `SelItem` (+ `Vertex`), candidates under the cursor in every
  category, box, Select Loop, the Shift + right-button menu, the drop-down.
- `gui/mod.rs`: `pick_filter` (the intersection for the frame) is computed once at the start
  of `viewport`; the shared picking functions (`edge_under`, `plane_under`, `vertex_under`,
  `work_axis_or_point_under`, `sketch_under`, the faces along the ray) consult it.
- `PickKind::Point` (vertex or work point) — for Work Point / Work Plane.
