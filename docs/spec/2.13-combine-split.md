# 2.13 Combine and Split (bodies and faces)

Status: ✅ done · 🟡 partial · ⬜ to do · ⛔ blocked by another feature.

All implemented rows are 🟡: checked with tests (`tests/combine_split.rs`), waiting for a visual
check in the application.

## 1. Purpose

**Combine** merges bodies of a multi-body part: one body is the base, the others are
tools. The result is Join (union), Cut (the base without the tools) or Intersect
(only the common volume).

**Split** cuts with a tool (sketch, work or origin plane, surface):
- **Split Face** splits only the faces. The body does not change, but one face becomes two and each
  can be tilted separately (Face Draft), deleted, etc.;
- **Trim Solid** removes one side of the body;
- **Split Solid** keeps both sides as two separate bodies.

## 2. Inputs

- **Combine:** Base (one solid body), Toolbodies (one or more other solid bodies),
  operation, Keep Toolbody.
- **Split:** method (Split Face / Trim Solid / Split Solid), tool (Split Tool), faces
  or body, side (for Trim Solid).

## 4. Browser and editing behaviour

| Behaviour | Inventor | Ours |
|---|---|---|
| Row in the browser | Combine1 / Split1 in the history; the tool sketch is nested under the Split | 🟡 the sketch is "consumed" (`Feature::sketch`), listed under the Split |
| Solid Bodies | the count is updated: consumed tools disappear, Split Solid adds a body | 🟡 hidden bodies have a faded name; Visibility in the context menu |
| Edit Feature | the dialog opens with the inputs; the part is shown as before the feature | 🟡 `rollback` + `replace_feature` |
| Delete | Combine: the tools come back; Split: the bodies and faces come back | 🟡 |
| Repetition in a pattern | Combine and Split are not repeated by themselves (Inventor repeats them only as part of a body) | 🟡 they do not store a `ToolSet`; a pattern of a Combine/Split refuses with "pattern the solid" |
| Dependencies | | 🟡 a piece `X~Split1.2` also depends on Split1 (`history::names_feature`) |

## 5. Edge cases and errors

| Case | Behaviour | Ours |
|---|---|---|
| A part with one body | Combine is not available (there is no tool) | 🟡 message `Combine: the part has one solid body …` |
| The base is also a tool | refusal | 🟡 |
| Cut without contact | refusal: the tool does not intersect the base | 🟡 |
| Intersect without a common volume | refusal | 🟡 |
| The tool does not cut the body | Split Solid / Trim Solid: refusal | 🟡 `the tool does not split the body` |
| A face the tool does not meet | Split Face: refusal, with the face's name | 🟡 |
| A body with a cavity | the SolidCraft kernel does not split such bodies with `split_body` | 🟡 then `split_by_plane` is used (Booleans with half-spaces) |
| A tool along a face | the kernel refuses | 🟡 the same fallback |
| A cut through the cone of a chamfer (SolidCraft #1691) | the volumes of the parts add up | 🟡 along the axis and at z = 19 through the cone: the sum matches to 2·10⁻⁶ (test) |
| Spiral (Coil) split by a plane (#793) | | ⛔ no Coil (2.7) |
| Shell without one piece of a split face | opens only the piece | 🟡 known bug: shell of a convex body in SolidCraft removes the whole plane (7152 instead of 8088 mm³ in the test) |
| Refusal | the part stays unchanged | 🟡 `insert_feature_checked` |

## 6. Implementation

- `part/combine.rs`: `CombineFeature` (`Feature::Combine`): `base`, `tools` (persistent body names),
  `operation`, `keep_tools`; exact build `build_exact` (Booleans in order; the result carries
  the base's name), faceted `build_faceted` (BSP). `PartDocument::add_combine`,
  `hidden_bodies`, `body_visible`; `bodies_before` skips the consumed bodies.
- `part/split.rs`: `SplitFeature` (`Feature::Split`): `method`, `tool` (`SplitToolRef::Plane /
  Sketch / Surface`), `faces`, `all_faces`, `solid`, `flip`, `keep_sketch_visible`;
  `resolve_tool`, `sketch_chains`, `build_exact`, `draft_pieces` (draft of a piece).
  `PartDocument::add_split`.
- `kernel/exact.rs`: `SplitBy`, `split_faces` / `split_faces_lenient` (`sk::split_faces_with_map`),
  `split_by_plane` (`sk::split_body`, fallback `sk::split_by_plane`), `face_corners`,
  `ExactSolid::rename_prefix`.
- Names: a face piece `<face>~<id>.<k>`; the section `<id>:Cut` (back or kept part) and
  `<id>#2:Cut` (front); with a closed loop `<id>:Cut:Side:<k>`; the new body `<id>#2`.
- GUI: `gui/combine_split.rs` (panels, selection, preview, arrow, OK/Apply), the selectors in
  `command/flow.rs` (`combine_selectors`, `split_selectors`), the shared menu and Enter in
  `gui/command_ui.rs`; hidden bodies are skipped in drawing and selection.
- Format: revision 13 (12 is reserved for Sweep/Loft), fixture `tests/compat/r13/`. The surface as a tool (`SplitToolRef::Surface`) and the open chains add nothing new to the file (the variant is from revision 13; the open curves of an Extrude Surface are `ExtrudeFeature::open`), so the revision is not bumped.
- Exact surfaces (`kernel/exact/sheet.rs`): `extrude_sheet`, `revolve_sheet` (SolidCraft), `ExactSolid::is_open` (the `sheet` field keeps a surface even when its shell closes), `SheetSide` (which side of the surface a point is on), `split_by_sheet`. During regeneration the surfaces do not enter the operations of the other features (only Split sees them). Faces `<id>:Side:<segment>`.
- Open chains: `split.rs::open_region` (extensions along the tangents, a counter-clockwise frame), `crosses_itself`.
