# 0.6d Pack and Go, and finding moved references

## 1. Purpose

A design is many files: assemblies link part files, drawings link the models of their views, and all of
them lie in a design project's folders (spec [0.6a](0.6a-file-types-projects.md)). Sending a design to
someone, archiving it or starting a variant from it needs **all** of those files, with links that still
work at the new place. Inventor's **Pack and Go** copies a file and every file it references into one
destination folder, writes a new project file for the copy and reports what it took. Ours does the same
for our file types, so a packed project is complete: opened anywhere, every link resolves.

The other half is what happens when a link's stored place is gone: Inventor first looks in the
project's folders (workspace, then libraries), and with *Using Unique File Names* it looks the file up by
its name anywhere in them. Ours does the same before a link is reported missing.

## 2. Inputs

- the source file: the active file (it must be saved) or one chosen with Browse;
- the destination folder (created when missing);
- the project whose folders lay the copy out: the active design project;
- the options below.

## 4. Browser and editing

Pack and Go changes nothing in the open files and adds no Undo step. The file's links are shown as before;
a link found by the project search is used as found and is not rewritten in the file until the user saves
(Inventor: Resolve Link writes the new path when the file is saved).

## 5. Edge cases and errors

- The source file not saved: `Pack and Go: save the file first`.
- The destination inside the source project's folder, or the destination equal to a source folder: refused
  (`Pack and Go: the destination is inside the project`), since the copy would pack itself.
- A link cycle (an assembly reached twice) packs each file once.
- A file that cannot be read stops nothing: it is listed and left out; Start stays possible.
- A name clash in Copy to Single Path is resolved by the ` (2)` suffix; the links follow the new name.
- Writing fails half way (disk full): the files already written stay, the message names the file that failed.

## 6. Implementation

- `document::pack` (GUI-free): `collect(root, project)` walks the links (`Project::libraries`) from the
  source file, `referencing(found, folders)` finds files that link into them, `plan(found, options)` decides
  each file's place in the destination, `run(plan, dest)` copies or re-saves and writes the new `.ccproj`.
- `document::design_project`: `DesignProject::find_link` (search order and unique names).
- GUI: `gui/pack.rs` (the window), command `file.pack_and_go` (`PG`, `Icon::PackAndGo`); link lookups go
  through `place.rs::link_path` with the active project.
