# 2.15 Materials and appearances (Materials, Appearances, Styles)

## 1. Purpose

Every part has a **material** and an **appearance**. The material carries the physical
properties — above all the density, from which the mass is computed (see
[0.10-physical.md](0.10-physical.md)) — and its own default appearance. The appearance is
visual only: colour, transparency, later roughness and metallic shine. The two are separate,
as in Inventor: a steel part can be painted red without changing its mass.

The appearance can be overridden at four levels: **face**, **feature**, **body**,
**part**. The more specific one wins: Face > Feature > Body > Part > the material's appearance.

## 2. Inputs

- **Libraries:** built-in (in the program) and user (in `%APPDATA%\3dcadcraft\materials\`,
  on Linux `~/.config/3dcadcraft/materials/`). A user entry with the same name replaces
  the built-in one.
- **Document copies:** every material and appearance in use is copied into the document, so
  the file looks and weighs the same on another machine, even without the same library (like
  "Document Materials / Document Appearances" in Inventor).
- **Selection for Adjust / the context menu:** faces, features or bodies from the view (the mode
  from Select in the Quick Access toolbar) or from the browser.

## 4. Browser and editing behaviour

- Overrides are stored **by persistent name**: the body by `Solid::name` (id of the creating
  feature), the feature by `id`, the face by name + point. After regeneration and after editing
  an earlier feature, the appearance stays on the same faces (test).
- A face whose name disappears simply loses its override (not an error). The entry stays in
  the file and comes back if the face appears again.
- **Assemblies (rule 8):** the part's material and appearance are properties of the part. The
  colour of an individual occurrence will live in the assembly (design view), not in the part.

## 5. Edge cases and errors

- An unknown material/appearance name in an old or foreign file: the built-in entry with the
  same name is used, otherwise the default appearance; the mass is computed with the Generic
  density and Physical Properties shows a warning.
- A bad row in a CSV: `Materials: <file> line N: <reason>`, the row is skipped.
- Density ≤ 0 or non-numeric: the row is refused.

## 6. How we implement it

- `src/materials.rs`: `Material`, `Appearance`, `Library` (built-in + user,
  CSV parser, `user_dir()`).
- `src/part/appearance.rs`: `Looks` (overrides + document copies), `Resolver`
  (precedence), `PartDocument::{set_material, set_appearance, clear_appearances, purge_styles}`.
- `src/part/physical.rs`: the mass (see 0.10).
- `src/part/export.rs`: GLB with materials; STEP through `kernel::exact::step_text_painted`.
- `src/gui/material.rs`: QAT lists, browsers, Adjust, Clear, Styles Editor, Physical
  Properties, the scene.
- Data: `data/materials/materials.csv`, `data/appearances/appearances.csv`.
