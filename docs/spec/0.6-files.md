# 0.6 Files: New, Open, Save, Save As, Export, recent files

## 1. Purpose

Working with the project file (`.3dcadcraft`) and exporting the part. In Inventor these are
the commands of the File menu (New, Open, Save, Save As, Export) and the list of recent
documents; when closing with unsaved changes the program asks whether to save. Inventor uses
the operating system's standard dialog; we have our own dialog in egui (the same on Linux and
Windows, with no dependency on GTK/COM).

## 2. Inputs

- a file path (picked in the dialog, typed by hand, from Open Recent or dropped with the mouse
  onto the window);
- for Export: the format (STL, STEP, GLB) and the file name.

### 3.0 The file dialog (Open, Save As, Export, Import)

Inventor shows the system's Open / Save dialog: a navigation pane with places on the left, the
folder's files in columns, the file name and the file type at the bottom, a preview. Ours follows
that layout in egui (one dialog for every purpose in `DialogPurpose`).

| Row | Behaviour | Our status |
|---|---|---|
| Window | resizable; opens centred on the first use, afterwards where and as large as it was left (`file_window` in the layout); the list takes the height the window gets | 🟡 waiting for the owner's check |
| Toolbar | Back, Forward, Up, Refresh and the folder path (editable; Enter goes there, `C:` means `C:\`) | 🟡 |
| Places pane | Recent, Desktop, Documents, Downloads, Home, This PC (Windows: the drives), and the folder of the current file; the place of the shown folder is highlighted | 🟡 |
| Recent place | the recent files with their folders, newest first; only files that still exist | 🟡 |
| Columns | Name (folder / project icon), Date modified (local time), Size (KB / MB; folders none); a click on a header sorts by it, a second click reverses; folders stay above files | 🟡 |
| Click / double-click | a click selects (a file also fills the name); a double-click opens the folder or the file (like Windows; a single click used to enter folders) | 🟡 |
| Keyboard | Up / Down move the selection, Enter opens it (or the typed name), Alt+Left / Alt+Right back / forward, Alt+Up or Backspace (outside the name field) the parent folder, Esc cancels | 🟡 |
| Typed name | a folder name or path typed with Enter goes into that folder; a full path is used as it is; the extension is added when missing | 🟡 |
| Files of type | the filter is shown below the name (e.g. `3DCadCraft project (*.3dcadcraft)`); only matching files are listed | 🟡 one type per purpose, no type choice |
| Speed | entries are read once per folder (type and metadata from the directory listing); only the visible rows are drawn, so folders with thousands of files scroll smoothly | 🟡 |
| Preview pane | the picked file's preview picture and its main properties beside the list (§3.0a) | 🟡 checked by the agent, waiting for the owner's check |

### 3.0a Preview picture (thumbnail) and properties preview

Inventor stores a small *preview picture* in every file when it is saved and shows it in the Open
dialog's preview pane (File → Properties → Save tab / Application Options → Save: Save Preview
Picture on by default; the picture comes from an isometric view of the component zoomed to fit, from
the active window at save, or from an imported image of fixed size). The Open dialog also shows the
file's summary properties.

| Row | Inventor behaviour | Ours | Our status |
|---|---|---|---|
| Save Preview Picture | on by default; off saves no picture | Application Options → Save: *Save preview picture* (on); off writes none (an old picture is dropped) | 🟡 checked by the agent in the app 2026-10-26, waiting for the owner's check |
| Source: isometric view | the component in an iso view, zoomed to fit, on every save | the default: the active document from the front-right-top corner, fitted, transparent background — the same model gives the same bytes (saves stay deterministic, folders do not change in git) | 🟡 checked by the agent in the app 2026-10-26, waiting for the owner's check |
| Source: active window on save | the graphics window's view | *Active view*: the camera's direction at save, fitted to the model (zoom and pan ignored so the part fills the picture) | 🟡 checked by the agent in the app 2026-10-26, waiting for the owner's check |
| Source: import from file | a picture of fixed size from a file | — | ⬜ |

| Speed | — | read on a worker thread (the zip's picture entry + the one document's properties), cached per file and time; the list never waits | 🟡 checked by the agent in the app 2026-10-26, waiting for the owner's check |

### 3.1 Document tabs (several open files)

Inventor keeps every open document in its own **document tab** along the bottom of the graphics
window: a click switches to it, the tab menu has Close / Close All / Close Other; each document has
its own view, selection and Undo; closing a changed document asks to save it.

| Row | Behaviour | Our status |
|---|---|---|
| Open / New in a tab | Open and New add a tab (no "save changes?" question, the other document stays open); opening a file that is already open switches to its tab; an untouched empty "Untitled" tab is replaced | 🟡 also a dropped file; a failed open removes its tab again (`gui/doc_tabs.rs`) |
| Tab bar | above the view: one tab per document — title (`*` when changed), `x` to close; a click switches | 🟡 plus `+` for New (deviation: Inventor has them along the bottom of the view) |
| Switching | the open command / sketch edit of the tab being left is finished (Finish Sketch) or cancelled (commands); each tab keeps its project, Undo history, file path, saved state, camera and selection | 🟡 the autosave / recovery file follows the active tab only |
| Close tab | `x` or the tab's right-click Close; a changed document asks Save / Don't Save / Cancel; closing the last tab leaves an empty Untitled one | 🟡 |
| Close Other / Close All | in the tab's right-click menu (each changed one asks) | 🟡 Close / Close Other (unchanged tabs close, changed ones stay); Close All ⬜ |
| Quit | every changed tab asks in turn (the first changed tab comes forward) | 🟡 Don't Save goes on to the next changed tab, Cancel stops the quit |
| Ctrl+Tab / Ctrl+Shift+Tab | next / previous tab | 🟡 taken in `raw_input_hook` before egui moves the focus |
| Tabs of one file | Inventor: one window per open document; a component opened from an assembly gets its own window and the assembly stays open; both show the same document in memory | several tabs may show documents of one design file (an assembly and a part of it). They form a *group* sharing one project, Undo history and saved state; only the view (document, camera, selection) is per tab. The project lives in exactly one place (the app's fields for the active group, else the group's holder tab, `doc_tabs::take_holding`). A tab title is `<file> › <document>` when the file holds several documents | 🟡 checked by the agent 2026-11-12 (§3.2), waiting for the owner |
| Closing one tab of a file | closing a window of a document that is still open elsewhere asks nothing | closes without a prompt while another tab shows the file; the last tab of the file asks as before; Close Other closes the kept file's other tabs and every unchanged file | 🟡 |

### 3.2 Files, documents and assemblies: end-to-end audit (2026-11-12)

The owner reported that opening a part created in an assembly *closed the assembly*. Every way a
document reaches the screen or the disk was reviewed against Inventor 2027's model: one document per
file, each open document in its own window, one copy of a document in memory however many windows
or assemblies show it, Save writing the document (and asking about changed dependents).

| # | Scenario | Inventor | Ours before | Ours now | Status |
|---|---|---|---|---|---|
| A1 | Open a component (browser / right-click Open) that is a document of the same design file | opens its own window; the assembly stays open | `activate_document` in the same tab: the assembly disappeared (only the browser's Return brought it back) — the reported bug | a tab of its own of the same file (`open_document_in_tab`); the assembly's tab stays; a tab already showing it comes forward | 🟡 fixed, checked by the agent |
| A2 | Open a component that is a linked part file | its window | the file's tab | unchanged | 🟡 |
| A3 | Documents node / Files tab / document menu of the tab / New Drawing in this file | — | replaced the tab's document | a tab of its own (spec 0.6b §3.2 already asked for a new tab) | 🟡 |
| A4 | Edits in the part's tab appear in the assembly | yes, the same document in memory | — | same project: the assembly shows them when its tab comes forward (patterns, frames, bolted connections, derived parts and cross-part references follow, `document_shown_again`) | 🟡 |
| A5 | Undo in either tab | one Undo per session | — | one Undo history per file, shared by its tabs; a tab whose document Undo (or Delete Document, Save to Separate File) removed closes (`prune_group_tabs`) | 🟡 |
| B1 | Create In-Place Component | asks the new file's name, template and location; writes a separate `.ipt` / `.iam`, then edits it in place | an internal document of the design file | **Store: Separate file** (default) writes `<New File Location or the assembly's folder>/<name>.ccpart` (`.ccasm` for an assembly template) and links it (`assembly::create::create_as_file`); an existing file is refused (another name); an unsaved assembly asks to be saved first; Edit in place then opens the new file's tab with the assembly around it. **Store: In this file** keeps the old behaviour | 🟡 fixed, checked by the agent |
| C1 | A linked part file open in its own tab with unsaved edits; the assembly comes forward | the assembly shows the edited part | the copy on disk (stale component) | the tab's project stands for the file in the assembly (`share_open_tabs`, by the tab's signature); it is read from disk again when the tab closes without saving | 🟡 fixed |
| C2 | The assembly changed a linked part (adaptive size, cross-part copies) and the part's file was then saved from its own tab | — (one document in memory) | the assembly's Save wrote its older copy over that save: **data loss** | the edit remembers when the file was last written (`Project::linked_bases`); a file saved since is not overwritten — the edit is dropped with a message and Update makes it again | 🟡 fixed |
| C3 | The assembly's Save while the linked part's tab has unsaved changes | Save asks about dependents | refused with a message (the part's changes would be lost) | unchanged | 🟡 |
| D1 | Save As / Save to Separate File onto a file open in another tab | refused (the file is open) | written; the other tab later saved over it | refused: `<file> is open in another tab: close it there first` | 🟡 fixed |
| D2 | Open of a file already open, by another spelling of its path | its window comes forward | compared the path text only (a second tab of the same file was possible) | also compared canonical paths | 🟡 fixed |
| D3 | Save As in one tab of a file | — | — | every tab of the file takes the new path and title (`sync_group_paths`) | 🟡 |
| E1 | Close a tab / Close Other / Quit with unsaved changes | asks per document | asks per tab | asks once per file (its last tab; Quit visits each changed file once) | 🟡 |
| E2 | Two tabs of the same file edited in turn | — | — | no copy exists to conflict: the second tab edits the same project | 🟡 |
| F1 | Edit in place of a part of this file, then switching tabs | — | the tab was left showing the part out of its context | Return to the assembly happens first (`end_local_in_place`) | 🟡 |
| F2 | Place, Replace, Make Part / Components, Derive, Pack and Go, design projects | — | reviewed: Place / Replace link by a path relative to the saved assembly (unsaved asks first); Make / Derive follow their sources when shown; Pack and Go works on files on disk (save first); switching the design project needs no changed document | unchanged | 🟡 |
| F3 | A linked file open in a tab that the assembly edits (C2 reversed) | — | the tab shows the file on disk, not the assembly's pending edit | unchanged: save the assembly first | ⬜ |

## 4. Browser and editing behaviour

Opening adds a tab (§3.1); the tab's Undo history starts empty. Saving does not change Undo.

## 5. Edge cases and errors

- Name `.`, `..` or empty — "Type a file name".
- A name typed in the list of drives, without a full path — "Pick a drive or type a full path".
- Missing folder — "No folder …"; missing file on Open — "No file …".
- Recent files are stored with a plain path (`C:\…`), not with the `\\?\C:\…` that
  `canonicalize` returns in Windows; the same applies to paths to libraries (Link), so they
  also work across different drives.
- The home folder in Windows is `USERPROFILE`: Git Bash sets `HOME=/c/Users/…`, which
  Windows cannot open.

  `src/document/format.rs`: `thumbnail.png` entry, `Manifest::preview`, `read_preview` → `FilePreview`;
  `src/gui/files.rs`: `preview_pane` (worker thread, `PreviewSlot`), `CadCraftApp::thumbnail_png`;
  Application Options › Save (`AppOptions::thumbnail`, `ThumbnailSource`).
- `src/document/library.rs`: `without_verbatim` for canonical paths.
- Tests: `gui::files::tests` (some only under `cfg(windows)`), `document::library::tests`.
