# 3.10 Top-down design

Status: plan and spec written 2026-10-29 at the owner's request ("a plan for top-down design and all its
functions"). Everything is ⬜ unless a row says otherwise. Several command panels already exist without
logic (rule 15: Create, Make Layout, Derive, Make Part, Make Components; spec 3.0 / 2.0).

## 1. Purpose

Top-down design starts from the product and its requirements, not from finished parts. Inventor supports
it with several mechanisms that work together:

- **in-place components**: a part or subassembly created and edited inside the assembly, sketched on the
  faces of its neighbours;
- **cross-part references**: geometry of one component projected into the sketch or feature of another,
  kept up to date when the source changes;
- **adaptivity**: an under-constrained part takes its size from the assembly;
- **derived components**: a part made from another part or assembly (chosen bodies, sketches, work
  geometry, parameters; scaled, mirrored), linked to it;
- **multi-body master parts**: one part holding every body, split into parts and an assembly by Make Part /
  Make Components;
- **layouts and skeletons**: a part of sketches (sketch blocks) or a skeleton that drives the whole product;
  Make Components turns its blocks into parts placed and constrained in an assembly;
- **assembly features**: cuts, holes, fillets and chamfers that exist only in the assembly and act on the
  components chosen as *participants*;
- **linked parameters**: a master parameter document whose parameters drive the parts.

This spec covers all of them, gives each an Inventor-like interface and our implementation, and sets the
order of work (§6).

## 2. Inputs

- An active assembly (in-place work, assembly features, adaptivity), or a part (Derive, Make Part / Make
  Components, layouts).
- Other components' faces, edges, vertices, work features and sketches, picked in the view or the browser.
- Documents of the same design file or linked files (spec 0.6b).

### 3.3 Cross-part references

| Item | Inventor behaviour | Our behaviour | Status |
|---|---|---|---|
| **Sketch on another component's face** | the sketch plane follows that face | `PlaneRef::Context(id)`: a context reference (below) to the face | ⬜ |
| **Project Geometry from another component** | edges / faces / loops projected into the edited part's sketch; associative when the option is on | `LinkSource::Context(id)`; the projected curves follow the source | ⬜ |
| **Extents / terminations on another component** | Extrude *To* a face of another part, work features on other parts | `FaceRef` / `PlaneRef` through a context reference | ⬜ |
| Where the reference lives | in the part, with the assembly it was made in (the part is "adaptive in that assembly") | `PartDocument::context: Vec<ContextRef>` — the source (assembly `DocRef`, occurrence path, persistent name / `EdgeRef`) **and a copy of its last geometry in part coordinates**. | **Update** (lightning icon) | the part is out of date when a source changed; Update (local) / Global Update rebuilds | the assembly compares each context copy with the current source (moved into the part's frame) at every solve; changed copies are written into the part, the part regenerates, the assembly solves again (≤ 8 rounds, then *does not settle* warning); the Update button turns active while one is out of date | ⬜ |

| **Break Link** | the projected geometry becomes plain sketch geometry | the reference is removed, its copy stays as fixed geometry (sketch: fixed reference curves → ordinary curves) | ⬜ |
| Missing source | the sketch / feature is sick | health: *the face X of Part:2 no longer exists* (rule 8) | ⬜ |

| Option **Enable associative edge/loop geometry projection during in-place modeling** (on) | edges of other parts projected automatically when sketching on them | auto-projection of the face's loop (as a part's own face, `PartSketch` auto-project) | ⬜ |
| Option **Features are initially adaptive** (off) | new in-place features made adaptive | `AppOptions::features_adaptive` | ⬜ |

## 4. Browser and editing behaviour

- An in-place edited component is highlighted in the assembly browser; its own features are listed below it
  (as Modeling View does) and the rest of the tree is greyed.
- Cross-part references show a chain glyph on the sketch / feature; out-of-date ones the Update glyph;
  right-click: *Break Link*, *Find Source*.
- Derived parts show their source under a Derive node (right-click: *Open Base Component*, *Update*, *Suppress
  Link*, *Break Link*, *Edit Derived Part*).
- Assembly features are listed under the assembly with their participants as children.

## 5. Edge cases and errors

- A context reference whose source is gone: the feature is sick and the last copy is kept (rule 5, rule 8).
- A part made adaptive in one assembly and placed in another: the second shows it as it is (not adaptive).
- An Update loop that does not settle within 8 rounds: *Update: the assembly does not settle (Part:2 ↔
  Part:3)*, nothing more is changed.
- Dependency loops (A derived from B derived from A, A projects from B projects from A): refused at pick time.
- Deleting a component that others reference: a warning listing the references that will become sick.

## 6. Implementation and order of work

New modules: `assembly::context` (context references, Update loop), `document::deps` (document dependency
graph, regeneration order), `part::derive` (`DeriveFeature`), `assembly::features` (assembly features and
participants). Every new `Feature` / `PlaneRef` / `LinkSource` variant is a format revision (check `main`
for the next free number first; peers take them too).

Order (each step spec → interface → logic → proof, as `CLAUDE.md`):

| Step | Content | Depends on |
|---|---|---|
| **T0** | Assembly work features and assembly 2D sketch; subassemblies S4 (browser, Open) | — |
| **T1** | Create In-Place Component (part / sheet metal / assembly, in this file or a new file, BOM structure, Virtual, Flush to the pick) | T0 for the sketch plane on an assembly plane |
| **T2** | Edit in place (in-place context, dimmed others, Return, Undo, linked files) | T1 |
| **T3** | Cross-part references (context copies, Update, Break Link, health, options) | T2 |
| **T4** | Adaptivity stage A (through references), then stage B (sketch DOF in the assembly solve) | T3; B also the solver |
| **T5** | Derive Part / Assembly + document dependency graph (Include / Exclude, styles, scale, mirror, Update / Suppress Link) | — (can run in parallel with T1–T4) |
| **T6** | Make Part, Make Components from bodies | T5 |
| **T7** | Assembly features with participants | T0 |
| **T8** | Sketch blocks, Make Layout, Make Components from blocks, skeleton modeling | T5, T6, sketch blocks |
| **T9** | Linked parameters (master document, CSV) | T5's dependency graph |
| **T10** | Break Link of Derive (stored bodies), Derive representations | STEP import, 3.9 |

Tests per step: in-place parts regenerate the same opened alone (rule 8); an Update loop moves a projected
edge with its source and settles; derived bodies keep volume × scale³ and mirror orientation (Euler, signed
volume); Make Components places each part exactly where its body was (8 box corners); an assembly cut changes
the participants' volumes and not the parts'; save / load round trips and compat fixtures for each revision;
perf cases (Update of 20 references, Make Components of 50 bodies).
