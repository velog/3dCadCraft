# 3.0 Assembly commands: the complete Inventor command set of the assembly environment (interface first)

Status: ✅ done · 🟡 partial · ⬜ to do · ⛔ blocked by another feature.

> Step AU0 of the roadmap's "Part and assembly interface review" (owner, 2026-10-27). Every
> command of Inventor 2027's assembly environment is listed here with its whole dialog. The order of
> work is the same as for the part (spec [2.0](2.0-part-commands.md), rules 7, 14, 15, 17): **spec →
> interface** (ribbon button with icon and alias, the dialog with every option, selectors that take
> picks, OK disabled) **→ logic**, command by command. Commands that already work keep their own specs
> (Place, constraints and joints in [3.1](3.1-assemblies.md), BOM in [3.6](3.6-bom.md)); their rows
> here only point there.

## 1. Purpose

The assembly ribbon carries Inventor 2027's assembly command set in Inventor's tabs and panels:
Assemble, Design, Inspect, Tools, Manage, View and Environments. Every command without logic opens
its dialog in Properties with all of Inventor's options and defaults; its selectors take picks in the
view (components, faces, edges, work and origin geometry). **OK and Apply stay disabled** until the
command's logic exists, so nothing changes the assembly (rule 5). The right-click menu of a selected
component offers every command that can take it (§3.8, rule 17).

## 2. Inputs

- The command set: Inventor 2027's assembly ribbon, tab › panel › command, in Inventor's order.
- Dialog options: Inventor Help 2027 (sources in §7). Rows marked *(to confirm)* come from general
  Inventor knowledge and are checked against the help before their logic is written.
- Picks: a **component** (occurrence) in the view or the browser; a **face**, **edge** of a
  component; origin / work geometry of a component or of the assembly (from the browser).
- Aliases: Inventor's where it has one, otherwise ours from the command name (rule 14); unique in the
  assembly environment.

## 3. Options

Status of every row: ⬜ until its interface exists, then 🟡 *interface done, logic ⬜*, ✅ only when
the logic passes its visual check. The dialog content is data in `gui/asm_planned.rs`
(`AsmPlanned::pages`), drawn by the same panel code as the part's planned commands.

**2026-10-27, interface step AU1:** every command whose "Dialog" column lists options in §3.1–3.6 is 🟡
*interface done, logic ⬜* (ribbon place, alias, own icon, the panel with tabs, selectors and
defaults). The display toggles (Show / Show Sick / Hide All) and the Environments tab are disabled
ribbon entries with their FEATURES section in the tooltip.

## 4. Browser and editing behaviour

- A planned command's dialog sits in Properties like the assembly's Constrain panel. The first
  selector is active; a click in the view becomes a pick of its kind — a component for component
  selectors (the occurrence's name), a face or edge of a component for geometry selectors. The next
  empty selector then becomes active; picking the same item again removes it; `x` clears a selector.
  Known gap (2026-10-27): a selector for straight edges / axes also takes a curved edge, and a planar-face
  selector any face; the kinds are checked when the logic comes.
- The status bar shows the active selector's prompt; Enter goes to the next selector; Esc closes.
- Started from a component's right-click menu (or with components selected), the selection fills the
  first selector (rule 17).
- Nothing appears in the browser until the logic exists.

## 5. Edge cases and errors

- Nothing is created: OK and Apply are disabled, their tooltip names the spec and FEATURES section.
- A planned dialog closes when the document changes (`leave_document`).
- A planned command is not offered for Repeat (Enter / Space).

## 6. Implementation

- `gui/asm_planned.rs`: `AsmPlanned` (one variant per command), `AsmPlanned::pages` (tabs and rows as
  data, the `Row` / `Page` types of `gui/part_planned.rs`), title / icon / FEATURES section / about.
  The dialog is the part's `PartDialog`, whose `kind` is a `Planned` (part or assembly command), so
  the flow, Enter, Esc, the right-click menu and the prompt (`command_ui` `Cmd::Planned`) serve both.
- Selector kinds in an assembly: `PickKind::Body` stands for a **component**; `Face` / `PlanarFace`,
  `Edge` / `StraightEdge` for a component's faces and edges (picked by `geom_under`); `Plane`, `Axis`,
  `Point` for origin / work geometry (from the browser later).
- `gui/commands.rs`: one entry per command (`Action::AsmPlanned(..)`, Bulgarian name, alias, own icon,
  `env(ASSEMBLY)`). `gui/ribbon.rs`: Assemble (Component, Position, Relationships, Pattern,
  Productivity, Simplification, Manage), Design (Fasten, Frame, Power Transmission, Spring), Inspect ›
  Interference; the assembly's Environments tab.
- Tests: every planned assembly command has a panel and a command with an alias and its own icon;
  selectors advance; aliases unique in the assembly environment.
