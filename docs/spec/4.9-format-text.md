# 4.9 Format Text, symbols and fields (drawing stage D-S2)

> Rich text for every drawing note: Text, Leader Text, and later the title block, sketched symbols, view
> labels and hole notes, which all reuse the same editor in Inventor.

## 1. Purpose

A note is more than one string at one height. Inventor's **Format Text** editor gives each selected piece of
text (a *run*) its own font, size, colour and style, gives the whole note justification, line spacing, width
factor, rotation, a border and a background fill, inserts drawing symbols from a grouped palette, and inserts
**fields**: values read from the model or the drawing (parameters, iProperties, sheet data, a parts-list cell)
that update when the source changes. The same editor opens for Text, Leader Text and every note editor that
lets the user type.

## 2. Inputs

- Text: a click on the sheet (the note's insertion point), then the editor.
- Leader Text: the leader's points (see 4.7), then the editor.
- Edit: double-click a note, or its right-click menu › Edit Text.
- A field's **Source**: the drawing, the active sheet, or the model of a view (picked from the list of the
  drawing's models; the model of the view the note is attached to comes first).

## 4. Browser and editing behaviour

- The editor previews the note live on the sheet while typing; OK writes one Undo step, Cancel leaves the note
  unchanged.
- Fields are evaluated every time the sheet is drawn (screen, PDF, DXF); a field whose source is gone shows
  `#?` in the note and the note is marked like an orphan.
- Double-click edits; the right-click menu offers Edit Text, Edit Leader (leader texts) and the layer / style
  lists (stage D-S1).

## 5. Edge cases and errors

- A font that is not installed falls back to the default font (the note keeps the font name).
- An empty note is not created (OK disabled).
- A stack marker without text on one side is kept as plain text.
- Fields read in part-local terms only (rule 8): a parameter field names the model and the parameter, never an
  occurrence.

## 6. Implementation (plan)

- `drawing::rich` (new, GUI-free): `RichText { paragraphs, justify, line_space, stretch, rotation, border, fill }`,
  `Paragraph { runs, list }`, `Run { content: Text | Symbol(id) | Stack(kind, a, b) | Field(FieldRef), style:
  RunStyle (font, size, colour or by-layer, bold, italic, underline, strike) }`, `FieldRef { source, kind, name,
  precision }`, layout into `Prim::Text` runs and lines (`layout(&RichText, look, &dyn Fn(&FieldRef) ->
  Option<String>)`), plain-text round trip for old notes.
- Storage: the Text / Leader Text annotations get an optional `rich` field (`#[serde(default,
  skip_serializing_if)]`); the old `text` stays as the plain-text copy so older builds still show the note. A
  new annotation kind would bump `FORMAT_REVISION` (next free 38).
- `Prim::Text` gains font / style flags (or a separate rich text prim) so the screen and the PDF draw runs; the
  PDF embeds the used fonts.
- GUI: `gui/format_text.rs` — the editor (run selection, toolbar, symbol palette, field picker), reused by Text,
  Leader Text and Edit Dimension's text tab.
- Symbols: our own vector glyphs in `drawing::symbols` (also used by GD&T and surface texture in D-S4).
