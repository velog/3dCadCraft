# 0.19 Long operations: progress and fast paths

## 1. Purpose

Most commands finish within the interaction budgets (rule 20). Some cases do not: a plate cut by
thousands of holes, a large file rebuilt from scratch. For those the user needs to see that the
program is working and how far it has got, and the program should take a shorter way where the
geometry allows one.

Inventor shows a progress bar in its status bar while a long update runs. Ours shows it in the
status bar too, with the step and the time spent.

A fast path is not something Inventor exposes. It is ours, and it can be switched off: it must give
the same body as the general kernel path (volume, faces, face names), so turning it off is only a
check.

## 2. Inputs

- the work that runs on a worker thread (previews, a Pattern's OK that takes its preview, linked
  files loaded by `LibCache`, and later every OK / Rebuild All, §3.3);
- the part's features being built (`build_features`): feature `k` of `n`, its name, its stage;
- for the fast path: the target body and the tool bodies of one Cut.

## 3. Options and behaviour

### 3.1 Progress

| Option | Inventor behaviour | Ours | Status |
|---|---|---|---|
| When it shows | during a long update | when one job has run for 1 s; hidden as soon as it ends | ✅ 2026-11-07 (Pattern preview of 1024 holes: shown after 1 s, gone at the end) |
| What it shows | a bar in the status bar | a bar in the status bar: `Building Pattern1 (5 of 9)`, the fraction of the features done, the time spent; a stage of a feature when it has one (`cutting 5041 holes`) | 🟡 2026-11-07: `Preview: building Rectangular Pattern1 (3 of 3)`, the bar at 2/3 and the seconds checked in the app; the stage (`Cut with N tools`) is cut off by the label width at 1400 px |
| Several jobs at once | — | the one that has run longest; the others are counted (`+1`) | 🟡 implemented (`+n`), not yet seen with two jobs |
| Cancel | Esc stops some updates | not in this step: the kernel cannot be stopped in the middle of an operation | ⛔ needs a stop check inside the kernel |
| The window stays usable | — | while a worker job runs the view can be orbited, panned and zoomed; commands that would change the part wait | 🟡 the view drew at 1 ms a frame during the preview; orbiting during a job not yet checked |

### 3.2 Fast path for many through cuts

| Option | Inventor behaviour | Ours | Status |
|---|---|---|---|
| Application Options › Part › *Fast path for many identical through cuts* | — | on by default; off sends every Cut through the general kernel Boolean | ✅ 2026-11-07 (the Part tab, ticked by default) |
| When it applies | — | a Cut (Extrude, Hole, a feature pattern of them) whose target is a prism along a direction `d` (two planar caps square to `d`, every other face parallel to `d`) and whose tools are prisms along `d` through both caps, each inside the caps' outer loop, apart from one another and from the holes already there | 🟡 Extrude and feature patterns of them (tests/through_cut.rs); Hole not yet |
| What it does | — | builds the result as the caps' profile with the tools' sections added as holes, extruded between the caps: no Boolean | ✅ 2026-11-07 (1024 holes 5.5 s with the solidcore sweep fixes, was 13-19 s; the general path 9.5 s) |
| Names | — | the same face names as the general path: the caps and walls keep the target's names, each hole wall the name of the tool face it came from | ✅ (tests/through_cut.rs: every name, volume and face count equal to the general path) |
| Anything else | — | the general path, unchanged | ✅ (over the edge, blind, overlapping: the general path) |

### 3.3 Work off the main thread

| Step | Ours | Status |
|---|---|---|
| Previews, Pattern OK, linked files | already on worker threads: they report progress | 🟡 Previews report and were checked in the app; Pattern OK and linked files not yet |
| OK of other commands, Rebuild All, Open | the part is built on a worker thread from a copy, the result is taken when it is ready (one Undo step); until then the view shows the old body with the bar | ⬜ |

## 4. Browser and editing

Nothing is stored in the part: progress is runtime state, the fast path is an application setting
(`AppOptions::fast_cuts`) and changes no file.

## 5. Edge cases and errors

- A fast path that cannot prove its conditions falls back to the general path; it never fails a
  feature on its own.
- Tests compare the fast and the general path on the same cases (volume, face count, every face
  name) and time them.
- A job that fails still clears its bar.

## 6. Implementation

- `part::progress`: a reporter installed per worker thread; `build_features` reports feature `k`
  of `n` and the stages of long features; the GUI reads the reporters of running jobs.
- `kernel::exact` fast path: the prism test, the profile with the new holes, one extrusion, the
  names carried over from the target and the tools.
- GUI: the status bar's bar (`gui/mod.rs` status bar), the option in Application Options › Part.
