# 0.19 Long operations: progress and fast paths

## 1. Purpose

Most commands finish within the interaction budgets (rule 20). Some cases do not: a plate cut by
thousands of holes, a large file rebuilt from scratch. For those the user needs to see that the
program is working and how far it has got, and the program should take a shorter way where the
geometry allows one.

Inventor shows a progress bar in its status bar while a long update runs. Ours shows it in the
status bar too, with the step and the time spent.

A fast path is not something Inventor exposes. It is ours, and it can be switched off: it must give
the same body as the general kernel path (volume, faces, face names), so turning it off is only a
check.

## 2. Inputs

- the work that runs on a worker thread (previews, a Pattern's OK that takes its preview, linked
  files loaded by `LibCache`, and later every OK / Rebuild All, §3.3);
- the part's features being built (`build_features`): feature `k` of `n`, its name, its stage;
- for the fast path: the target body and the tool bodies of one Cut.

### 3.3 Work off the main thread

Inventor runs an update on its main thread: the window repaints and Esc can stop some updates, but
nothing else can be done until it ends. Ours builds the part on a worker thread from a copy of it, so
the view stays usable; editing waits, as in Inventor.

| Step | Ours | Status |
|---|---|---|
| Previews, Pattern OK, linked files | already on worker threads: they report progress | 🟡 Previews report and were checked in the app; linked files not yet |
| OK of a command | the command's feature is added (or replaced) on a copy of the part on a worker thread (`gui/background.rs`, `part_job`, 64 MB stack, its own progress reporter). The command's panel stays open, shown disabled with "<Command>: building... (Esc cancels)"; the view shows the old body with the bar (§3.1). When it finishes the Undo checkpoint is recorded with the state before the OK and the copy replaces the part: one Undo step, as before. Families: Extrude / Revolve, Fillet / Chamfer, Face Draft, Shell, Combine, Split, Sweep, Loft, Coil, Rib, Hole / Slot, Thicken, Delete Face, Move Bodies, Rectangular / Circular Pattern and Mirror, sheet metal commands, planned part panels with logic (surface commands, plastic parts) | 🟡 implemented 2026-11-19; checked in the app: Edit Feature of an Extrude on the owner's lid file (panel locked while building, one Undo step); work features (fast) stay synchronous |
| Preview reuse | an OK whose preview already built the same thing takes the preview's part at once (`take_preview_part`, Pattern), no job | 🟡 Pattern only, as before |
| Edit after a drag | a manipulator released on an existing feature, Edit Feature of a target, a value typed into a feature's Properties (`commit_feature_fields`): the same job (label *Edit Feature*) | 🟡 2026-11-19: Box1 Length 310 → 320 mm on a 900-hole plate built in the background (`Edit Feature: building Rectangular Pattern1 (3 of 3)` in the bar), Undo back to 310 in one step |
| Rebuild All | the same job without an Undo step (the data does not change); the status bar's result when it ends | ✅ 2026-11-19: 900-hole plate, 8.1 s in the background, the view orbited during it, `Rebuild All: 3 features in 8.09 s` |
| Open | the part of a file opened from disk is still rebuilt on the main thread | ⬜ |
| Edits while it runs | only the view changes: orbit, pan, zoom, ViewCube, standard views, visual style, projection, Measure, Help (`background::allowed_while_building`). Every other command, Undo / Redo, switching documents or tabs is refused with "<Command>: <job> is still building; wait or press Esc to cancel it". The browser and the command panel are shown but locked | 🟡 2026-11-19: Ctrl+Z refused with that message, orbit and hover work while building, browser and Properties greyed; Measure during a job not yet tried |
| Changed meanwhile | the result is taken only if the document is still the active one and `part_signature` is unchanged; else it is dropped with "<Command>: the part changed while it was built; press OK again" | 🟡 implemented 2026-11-19 |
| Failure | the feature's error as before (`<Command>: <reason>`), the part unchanged (rule 5; a failed Edit Feature stays rolled back to the edited feature), the bar cleared | 🟡 implemented 2026-11-19 |
| Cancel (Esc) | the job is dropped at once ("<Command>: cancelled"), the panel stays open. | Assemblies | solving and frame member rebuilds stay on the main thread | ⬜ (frame member rebuilds already run in parallel threads, but the frame waits for them) |

## 4. Browser and editing

Nothing is stored in the part: progress is runtime state, the fast path is an application setting
(`AppOptions::fast_cuts`) and changes no file.

## 5. Edge cases and errors

- A fast path that cannot prove its conditions falls back to the general path; it never fails a
  feature on its own.
- Tests compare the fast and the general path on the same cases (volume, face count, every face
  name) and time them.
- A job that fails still clears its bar.

## 6. Implementation

- `gui/background.rs`: the one job slot (`CadCraftApp::bg`), `part_job` (copy, worker, take), `bg_tick`,
  `bg_cancel`, the commands allowed while it runs.
- `part::progress`: a reporter installed per worker thread (a cancellable one for background jobs); `build_features` reports feature `k`
  of `n` and the stages of long features; the GUI reads the reporters of running jobs.
- `kernel::exact` fast path: the prism test, the profile with the new holes, one extrusion, the
  names carried over from the target and the tools.
- GUI: the status bar's bar (`gui/mod.rs` status bar), the option in Application Options › Part.
