# 0.17 Home (start page)

## 1. Purpose

Inventor opens on **Home**: a page that is not a document, where the user picks the active project,
starts a new file from a template, reopens a recent file, or follows a link to learning material. It
comes back whenever every document is closed, and it can be reached at any time from its own tab.
Ours follows its layout so a user coming from Inventor finds things in the same place.

## 2. Inputs

- the active design project and the list of known projects (spec [0.6a](0.6a-file-types-projects.md));
- the recent files (`settings.json` `recent_files`, per project), their preview pictures and
  iProperties (`document::format::read_preview`);
- the templates (§3.2).

## 4. Browser and editing behaviour

Home has no browser, no Properties and no Undo. Pins, the view mode, sorting and columns are user
settings (`settings.json`), never document data.

## 5. Edge cases and errors

- No recent files: an empty-state card with New and Open.
- A preview that cannot be read (old or broken file): the kind icon instead of the picture.
- Thousands of recent entries are impossible (≤ 199); previews are read on a worker thread and cached
  per file and time (the Open dialog's `PreviewSlot`), so the page never waits for the disk.

## 6. Implementation

- `src/gui/home.rs`: `HomeUi` (view mode, sort, search, filter, selection), the page, the card menu.
- Recent list: `settings.json` `recent_files` stays a list of paths (older builds read it); Home's own
  settings — Show on startup, view, sort, pins — are the `home` key (`HomeSettings`).
- Thumbnails: `read_preview` on one worker thread per card, textures cached per path.
- Command entries in `gui/commands.rs` (⬜, when the file is free of other sessions' edits): Home
  (alias `HM`), Projects (alias `PJ`).
- Hooks: `doc_tabs.rs` (`home_tab`, Home after the last close), `layout.rs::docked_panels` (no browser /
  Properties, `home_page` instead of the view), `new_file.rs::new_file_of`.
