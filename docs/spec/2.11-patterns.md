# 2.11 Rectangular Pattern and Circular Pattern (patterns of features and bodies)

## 1. Purpose

Repeats features (a hole, a boss, a pocket) or a whole body:
- **Rectangular:** in one or two directions, at equal spacing;
- **Circular:** around an axis, at equal angles.

The copies follow changes to the original. A pattern of bodies also copies features that
cannot be repeated on their own (Shell, Fillet of all edges).

## 2. Inputs

- **Features** (the default) or **Solids** (a whole body): what is repeated.
- Rectangular: **Direction 1** and optionally **Direction 2**. A direction is a straight edge, an origin
  axis, a work axis or a planar face/plane (its normal).
- Circular: **Rotation Axis**: an origin axis, a work axis or a straight edge.
- Count (including the original), spacing or total distance/angle.

## 4. Browser and editing behaviour

- `Rectangular Pattern1` / `Circular Pattern1` (id `RectangularPattern1` /
  `CircularPattern1`) after the features it repeats; the tooltip shows the count and spacing.
- Edit Feature (double click, context menu, Properties) opens the panel; the model is rolled back
  to before the pattern. A change to the original (e.g. hole depth) also changes the copies on
  regeneration. Count, Spacing and Angle can also be changed in Properties (with expressions).
- The face names of copy k (the original is 1) are `<pattern id>#k:<name in the original>`,
  for example `RectangularPattern1#2:Extrusion2:Side:C1:0`. A click on such a face selects the
  pattern. A fillet on an edge of a copy stays tied to the same copy.
- A pattern of a pattern (or a mirror of a pattern) copies all its copies together with the original.

## 5. Edge cases and errors

- A repeated feature that cannot be copied on its own (Shell, Draft, Fillet, Chamfer):
  "<feature> cannot be patterned on its own (pattern the solid)".
- A copy that does not intersect the body in a Cut simply does nothing (so does Inventor). There is an
  error only if no copy intersects: "Cut: none of the copies intersects the body".
- A copy of a Join that does not touch the body becomes a separate piece (lump) of the same body.
- The copies cut/merge only the bodies the original selected (`solids`) — SolidCraft
  #2755 is a bug exactly here.
- More than 10000 copies: refused with "too many instances" (SolidCraft has 1000). Speed (release): 1000 holes ~1 s, 5000 ~7 s, 10000 ~14 s, circular pattern of 5000 ~9 s, Join of 1000 bosses ~10 s ([PERF](../PERF.md)).
- A failed pattern does not change the part (`add_pattern` restores the previous state).
- The kernel fails: feature error (no faceted rebuild).
- Known problems in SolidCraft: a pattern of a Join is quadratic (#2076). In ours the copies
  of one feature are gathered with `union_apart` into one tool and the body is cut/merged
  once: 100 bosses ~1.4 s.

## 6. Implementation

- `part::pattern::PatternFeature` (`Feature::Pattern`, `PatternKind::{Rectangular {
  first, second }, Circular, Mirror}`, `PatternDirection`), `placements` gives the
  matrices of the copies (the original is 1, the copies 2…N).
- Regeneration (`PartDocument::build_features`) keeps the tools of every Extrude /
  Revolve (the bodies before `exact::combine`, with the operation and the selected bodies) by feature
  id (`pattern::ToolSet`, also in `CachedStep`, so they exist on a cache hit too).
  `part::exact::pattern` copies them with `kernel::exact::transformed` (`sk::transform_matrix`)
  and applies them with the same operation via `exact::combine(.., lenient)`. A new kind of feature with
  tools (Hole) is added just by recording a `ToolSet`.
- Solids mode: whole bodies are copied (Join: `union_apart` + union with the original).
- GUI: `gui/pattern_feature.rs` (selection, arrows, preview, OK/Apply), the panel and Properties
  in `gui/panels.rs`.
- Tests: `part::pattern::tests`, `kernel::exact::tests` (`transformed`),
  `tests/matrix.rs` ("rect pattern …", "circ pattern …", "pattern …", SolidCraft #2076,
  #2755), `tests/perf.rs`, `tests/compat/r5/pattern_r5`.
