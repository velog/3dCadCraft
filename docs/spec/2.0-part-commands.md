# 2.0 Part commands: the complete Inventor command set of the part environment (interface first)

Status: ✅ done · 🟡 partial · ⬜ to do · ⛔ blocked by another feature.

> Owner's request (2026-10-27, after the part / assembly interface review — `docs/ROADMAP.md`
> "Part and assembly interface review"): every command of Inventor's part environment is described here
> with its whole dialog, then built as an interface (ribbon button with icon and alias, the dialog with
> every option, selectors that take picks, OK disabled), then filled with logic command by command
> (rules 7, 14, 15, 17). Commands that already work keep their own specs (Extrude 2.1, Revolve 2.2, Hole
> 2.3 …); their rows here only point there. The sheet metal commands are in [5.6](5.6-sheet-metal.md),
> the sketch commands in 1.x, the drawing commands in [4.7](4.7-drawing-commands.md).

## 1. Purpose

The part environment's ribbon carries Inventor 2027's full command set in Inventor's tabs and panels:
3D Model, Inspect, Tools, Manage, View and Environments. Every command that has no logic yet opens its
dialog with all of Inventor's options, defaults and selectors. You can try the dialog, and the selectors
take picks in the view (faces, edges, bodies, sketches, work features). **OK and Apply stay disabled**
until the command's logic exists, so nothing changes the part (rule 5). The right-click menus offer
every command that can take the selected object (§3.9, rule 17).

## 2. Inputs

- The command set is Inventor 2027's part ribbon: tab › panel › command, in Inventor's order.
- Dialog options come from Inventor Help 2027 (sources in §7). Rows marked *(to confirm)* come from
  general Inventor knowledge. They are checked against the help before their logic is written.
- Aliases: Inventor's where it has one, otherwise ours from the command name (rule 14). None of them
  may collide with another alias of the part environment (the registry test checks this).

## 3. Options

Status of every row below: ⬜ until its interface exists. After the interface step it is 🟡 *interface
done, logic ⬜*. It becomes ✅ only when the logic passes its visual check. The dialog content is the
data in `gui/part_planned.rs` (`PartPlanned::pages`), built like `gui/drawing_planned.rs`.

**2026-10-27, interface step P2:** every command with a panel in §3.1–3.8 (the rows whose "Dialog" column
lists options, except Start 3D Sketch, Decal's sketch images, Region Properties, Cross Section Analysis,
Repair Bodies, Fit Mesh Face, Shape Generator, Stress Analysis, Insert Object, Customize, the View display

a face selected first), Grill (alias GRL, five tabs, right-click menu); the tabs Inspect, Manage, View,
Environments.

### 3.9 Right-click menus of the part (rule 17)

Each menu lists every command that can take what is under the cursor or selected. Starting a command
from it fills the command's first selector with that selection. Today (2026-10-27) a face offers
Appearance, Measure, Projection, New Sketch and a mini-toolbar with 5 icons; an edge offers Fillet and
Chamfer in the mini-toolbar only.

Commands with a panel already fill their first selector from the selection when started (P2). **P3
(2026-10-27, `gui/sel_menu.rs`):** a right click on something not selected selects it; the menu's top lists
the selection's commands by kind (planar / curved face, straight / curved edge, vertex, solid, surface body,
sketch, work plane / axis / point; a mixed selection gets what takes all of them; one-item commands only for
one item). Each starts with the selection as its first input: New Sketch on it, Press/Pull, Hole (its face),
Shell (faces to remove), Face Draft (faces, Pull Direction active), Thread (the cylinder), Fillet / Chamfer
(the edges), Work Plane / Axis / Point (the face, edge, vertex or work feature), Combine (the base), Split
(a work plane or surface as the tool), Extrude / Revolve (the sketch), Edit Feature / Edit Sketch / Look At,
and the planned panels. Checked in the app: a face's menu, Face Draft, Work Plane, Copy Object. Rows below
are 🟡 (Find in Browser, Hide / Isolate, Select Other in the menu, Show Dimensions ⬜).

## 4. Browser and editing behaviour

- A planned command's dialog sits in the Properties panel, like the other part commands (`0-ui.md`
  §2.9). The first selector is active. A click in the view becomes a pick of the selector's kinds
  (face, edge, vertex, body, sketch, work feature; `PickKind`). The next empty selector then becomes
  active. Picking the same item again removes it; `x` clears a selector.
- The status bar shows the active selector's prompt. Enter goes to the next selector; Esc closes.
- Started from a right-click menu, the selection fills the first selector (rule 17).
- Nothing appears in the browser until the logic exists.

## 5. Edge cases and errors

- Nothing is created: OK and Apply are disabled and explain why in their tooltip
  (`Planned — docs/FEATURES.md, section …`).
- A planned dialog closes when the document changes (`leave_document`) and on Finish Sketch.
- A planned command is not offered for Repeat (Enter / Space).

## 6. Implementation

- `gui/part_planned.rs`: `PartPlanned` (one variant per command), `PartPlanned::pages` (tabs and rows as
  data, the `Row` / `Page` types of `gui/drawing_planned.rs`), the dialog state (values per tab and row,
  picks per selector, auto-advance). Numbers use `ExprValue` (rule 13). Selector kinds map to `PickKind`s
  so `update_pick_filter` and the shared pickers serve them.
- `gui/commands.rs`: one entry per command (`Action::PartPlanned(..)`, Bulgarian name, alias, own icon).
  `gui/ribbon.rs`: the 3D Model panels in Inventor's order (Sketch, Create, Modify, Explore, Work
  Features, Pattern, Surface, Plastic Part, Freeform, Convert, Simulation), Inspect › Analysis, Manage ›
  Author / Insert / Layout, View › Appearance, and the Environments tab. The panels must fit 1400 px:
  rarely used commands go into split buttons or `.mini()`.
- `gui/keys.rs`: an open planned dialog is part of `open_state`.
- Tests: every planned command has a dialog and a command; selectors advance; aliases unique; ribbon
  places exist.
- When a command gets its logic, it moves to its own module and spec. Its row here then points there.
