# 4.4 Assembly views, Parts List and balloons

Status: ✅ done · 🟡 partial · ⬜ to do · ⛔ blocked by another feature.

> Stage 1 of the drawing tools (owner, 2026-10-26): assembly views, Parts List, Balloon, Auto Balloon. The
> owner's main requirement is a **very flexible BOM with no manual work**: columns from any property, cell
> overrides that survive changes, sort and renumber, hidden and custom rows, wrapping, balloons that read
> item numbers through the parts list.

## 1. Purpose

Draw an assembly in a drawing view, put its bill of materials on the sheet as a table, and number its
components with balloons. The table and the balloons always come from the current assembly: a new
component, a changed part number or a removed occurrence updates them. Only the user's own decisions are
stored.

## 2. Inputs

- An assembly of this project, or a linked assembly file, as the model of a Base View (the Base View list
  shows parts and assemblies). Its components are reached as the assembly reaches them: parts of the same
  project or part files linked relative to the assembly's file.
- The assembly's BOM (`docs/spec/3.6-bom.md`): Structured (first level) and Parts Only, Part Number Row
  Merge, the components' iProperties.

## 4. Browser and editing behaviour

- Parts lists and balloons belong to their view: deleting the view deletes them (Inventor keeps a parts list
  whose view is gone; ours needs the view to find the model).
- Delete removes the selected one; Undo / Redo as every drawing edit.
- PDF export draws them as on screen (one display list).

## 5. Edge cases and errors

- A view still being computed: its parts list draws as soon as its BOM is known; balloons wait for the lines.
- A linked component file that is missing: its row reads `(missing) <file>`.
- A changed part number: overrides of the old number stop applying (they are kept in the file).

## 6. Implementation

- `drawing::parts` (GUI-free): `PartsList`, `Column`, `SortBy`, `CellOverride`, `CustomRow`, `Wrap`,
  `table` (rows → `Table` with the item of each occurrence), `table_prims`, `bounds`, `Balloon`,
  `BalloonShape`, `balloon_prims`, `Tables` (per sheet and frame: view models, BOM rows, items through the
  parts lists of the whole drawing). `annot::resolve_in` draws them; `resolve_with` is the same without
  tables.
- `drawing::hlr::assembly_model` / `Instance` (one model per component, moved per occurrence).
- `assembly::bom::BomRow::props`: the standard iProperties for columns.
- GUI `gui/drawing_bom.rs`: `drawing_assembly` (`AsmSrc::Local` / `File`), `model_job` (copies for the
  worker), `assembly_signature` (view cache key), `bom_rows`, `bom_tables`, the three commands, the editor.
- Format revision 25 (`AnnotationKind::PartsList` / `Balloon`); fixture `tests/compat/r25`.
- Tests: `drawing::parts::tests`, `drawing::tests::assembly_parts_list_and_balloons`,
  `gui::drawing_bom::tests::balloon_placement`, `compat::drawing_r25_reads`.
