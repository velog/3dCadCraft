# 0.7 API for agents: the MCP server

**Status:** 🟡 phase 2 — headless server over stdio with the part, sketch, assembly and query
tools, face / edge aliases, the AI action log and a read-only mode; the running app hosts the same
tools for an agent (§3.9, Tools › AI Connector). Remote access (HTTP) is a later phase. FEATURES [0.7](../FEATURES.md#07-api-for-agents-json-rpc--mcp).

## 1. Purpose

AI agents (Claude Code, Claude Desktop and any other Model Context Protocol client) drive
3DCadCraft without its window: they create a project, sketch with constraints, build features,
read back names, sizes and health, and save a file the GUI opens. Every changing call is one Undo
step. The Inventor counterpart is its COM API and Rules (iLogic); we expose CAD operations with
Inventor's command names, not Inventor's object model.

Lessons from agents driving SolidCraft's MCP server (ROADMAP E, `SOLIDCRAFT_ISSUES.md`) are
requirements here: long work observable and cancellable, atomic batches that name the failing
entry, compact answers, a repeated name refused rather than renamed.

## 2. Transport

| Item | Behaviour | Status |
|---|---|---|
| stdio | The client starts the server and exchanges JSON-RPC 2.0 messages, one per line (UTF-8, no raw newline inside a message), on stdin / stdout. Nothing else is written to stdout; diagnostics go to stderr. | ✅ |
| Binaries | `3dcadcraft-mcp [PROJECT]` (package `cadcraft3d-core`, no graphics stack) and `3dcadcraft --mcp` (the desktop binary, no window). PROJECT is opened before the first message. | ✅ |
| Protocol versions | `initialize` answers the client's version when it is one of 2025-11-25, 2025-06-18, 2025-03-26, 2024-11-05, else 2025-11-25. Capabilities: `tools`, `resources` (no list-changed notifications). `instructions` give the typical call order. | ✅ |
| `ping` | Answered at any time, also while a call runs. | ✅ |
| Shutdown | The server ends when stdin closes (MCP stdio shutdown). A call still running is abandoned. | ✅ |
| Streamable HTTP | Owner's decision 2026-11-19: stdio only for now (Claude Code, Claude Desktop and other local clients start the server themselves). A later **Remote** phase adds Streamable HTTP with authentication; no network listener before it (§3.6). | ⬜ |
| Attach to the app | `3dcadcraft --mcp --attach` (or `3dcadcraft-mcp --attach`) is the same stdio server for the client, but it forwards every message to the running app over a local pipe (§3.9); when no app accepts connections it serves headless (a note on stderr and in `status`). | ⬜ |
| Command line | `--read-only` (§3.6), `--attach`, then an optional PROJECT (headless only; an attached app keeps its own project). | ⬜ |
| Tasks (2025-11-25 `tasks`) | Not declared; long work uses progress + `status` + `cancel` (§3.7). | ⬜ |

## 3. Behaviour

### 3.1 Project tools

| Tool | Behaviour | Status |
|---|---|---|
| `status` | Project name, file, active document, documents with kind, unsaved flag, Undo / Redo labels, running work with progress text and seconds. Answers while another call runs (`busy` names it). | ✅ |
| `project_new` | A new empty project; Undo history cleared. | ✅ |
| `project_open` | Opens a `.3dcadcraft` file or folder and rebuilds every part from its features (display triangles and work geometry are not saved); feature failures are listed as `health`. | ✅ |
| `project_save` | Saves to `path` or the file it came from; atomic and deterministic (the file format's own save). | ✅ |
| `document_new` | Adds a part or an assembly and activates it. A name already used is an error, never a silent rename. | ✅ |
| `document_activate` | Another document becomes the active one. | ✅ |
| `undo` / `redo` | Whole calls; a batch is one step. | ✅ |
| `batch` | `{commands: [{tool, arguments}]}` run in order on one copy of the session: all succeed or nothing changes; the error reads `Batch: entry <i> (<tool>) failed, nothing was changed: <Command>: <reason>`. Project, Undo, Save and nested batches are refused inside. | ✅ |

### 3.2 Sketch tools

Points, curves and constraints are named by handles `p<n>`, `e<n>`, `c<n>`, stable for the
sketch's life (the arena slot). Coordinates are sketch mm; `sketch_create` returns the plane's
origin and axes in model space so the agent can map between them.

| Tool | Behaviour | Status |
|---|---|---|
| `sketch_create` | On an origin plane (XY default, XZ, YZ) or a planar face by persistent name. The origin is projected (a fixed point, `projected_points`); on a face its edges are projected as reference lines (Inventor's Autoproject). | ✅ |
| `sketch_line` | Ends are `[x, y]` (new points) or handles (shared points: a connected chain needs no Coincident). | ✅ |
| `sketch_rectangle` | Two Point Rectangle, or Center (`center: true`): 4 lines with Horizontal / Vertical. | ✅ |
| `sketch_circle`, `sketch_arc`, `sketch_point` | Center Point Circle, Center Point Arc (a new end moved onto the circle through the start), Point / Center Point. | ✅ |
| `sketch_constrain` | Any constraint kind by its type name with handles (Coincident … Diameter); Angle in degrees. Solved at once. Refused, with nothing changed, when it adds redundancy (Inventor's "over-constrains the sketch") or does not solve. A dimension gets its parameter name (`d0`). | ✅ |
| `sketch_info` | Points, curves (kind, point handles, projected flag), closed regions (index, area, a point inside), DOF and redundancy; `detail` adds the constraints. | ✅ |
| Spline, polygon, slot, offset, trim, sketch patterns | Through later tools. | ⬜ |
| Driven dimensions | ⬜ | ⬜ |

A geometry or constraint change of a sketch a feature already uses rebuilds the part; a feature
it breaks fails the call.

### 3.3 Feature tools

Each goes through the part's own `add_*` operation, so ids (`Extrusion1`, `Hole1`), persistent
face names and failures are those of the GUI command. A feature that fails is refused (the part
is rebuilt without it, rule 5).

| Tool | Behaviour | Status |
|---|---|---|
| `extrude` | Regions by index (default: the sketch's own closed regions, as the Extrude command starts); distance or Through All; Default / Flipped / Symmetric; Join / Cut / Intersect / New Solid (default New Solid for the first body, Join after); taper. | ✅ |
| `revolve` | About X / Y / Z or a sketch line; full or an angle. | ✅ |
| `hole` | On a planar face at model points (a hole sketch with Center Points is made, as Hole's Allow Center Point Creation): Simple (diameter, depth / Through All), Clearance (ISO 273 size and fit, through), Tapped (ISO metric size, depth / Through All). Built-in standards tables only (the user's tables would make a call depend on the machine). | ✅ |
| `fillet`, `chamfer` | Constant radius / equal distance on edges named `FaceA\|FaceB`. | ✅ |
| `shell` | Thickness, faces to remove, Inside / Outside / Both. | ✅ |
| `pattern` | Rectangular (one or two directions: X / Y / Z or a straight edge) and Circular (about X / Y / Z) of features. | ✅ |
| `mirror` | Features mirrored about a plane (origin plane, face or alias, work plane). | ⬜ |
| `work_plane` | Offset from a plane (distance), Midplane of two planes, Angle to a plane about a line (degrees). Returns `WorkPlane<n>`, usable as a sketch plane (`sketch_create {plane: WorkPlane1}`) and a mirror plane. | ⬜ |
| `work_axis` | Intersection of two planes, through a circular edge, normal to a plane through a point. | ⬜ |
| `work_point` | Fixed at [x, y, z], intersection of three planes, of a plane and a line. | ⬜ |
| `sweep` | Regions of a profile sketch along a path: curves of another sketch (handles, chained) or model edges; Join / Cut / New Solid as Extrude. | ⬜ |
| `loft` | Through two or more sections: each a sketch region `{sketch, region}` or a sketch point `{sketch, point}` (first / last only); Join / Cut / New Solid. | ⬜ |
| Coil, rib, draft, thread | ⬜ | ⬜ |

### 3.4 Parameters and queries

| Tool | Behaviour | Status |
|---|---|---|
| `parameters` | Every parameter: name, value in its unit, unit, equation, owner. | ✅ |
| `parameter_set` | Value or equation (`"120 mm"`, `"d0 / 2"`), then a rebuild; refused when it does not evaluate or a feature fails. | ✅ |
| `features` | The feature tree (id, type, name when renamed, health, suppressed), sketches with DOF and users, solid count, exact or faceted. Also the resource `cadcraft://part/<name>/features`. | ✅ |
| `faces` | Persistent names with surface type; `detail` adds area, centre, plane normal. | ✅ |
| `edges` | `FaceA\|FaceB` (sorted), kind (line / circle / curve), length. | ✅ |
| `measure` | One or two items (face, edge, vertex, body, point): lengths, areas, radius, position; minimum distance with the closest points, centre distance, angle. | ✅ |
| `physical` | Volume, area, mass (g), centre of gravity, bounding box, material, warnings. | ✅ |
| `export` | STEP, STL, glTF by extension or `format`. | ✅ |

### 3.4a Names, aliases and descriptions of faces and edges

Persistent names (rule 2: `Extrusion1:End`, `Extrusion1:Side3`) stay the only names the part
stores; agents get short aliases and a description to choose the right face without reading
coordinates. Owner's decision 2026-11-19.

| Item | Behaviour | Status |
|---|---|---|
| Description | `faces` lists every face as `[name, surface, alias, dir]`: the surface kind, an alias when one exists and, for a plane, its outward normal as `+X` … `-Z` when it lies along an axis (else the rounded normal); `detail` adds area, centre, normal and the radius of cylinders, cones, spheres. | ⬜ |
| Aliases of a feature's planar faces | `<feature>:<dir>` (`Extrusion1:+Z`) and the view word of that direction (`Extrusion1:Top` = +Z, `Bottom` −Z, `Right` +X, `Left` −X, `Back` +Y, `Front` −Y; Z up, the view cube's names) when exactly one face of that feature has that normal. A real persistent name always wins (`Box1:Top` is a name of its own). | ⬜ |
| Aliases of the part | `+X` … `-Z` and `Top` … `Front` alone: the outermost planar face with that normal (largest centre along it), when no other face lies in that plane. | ⬜ |
| Arguments | Every argument that takes a face (sketch_create, hole, shell, measure, constrain, mirror, work features) takes a name or an alias; edges `FaceA\|FaceB` take aliases on either side (`Top\|+X`). | ⬜ |
| Answers | Always persistent names (`Extrusion1:End`), never aliases: an alias can change meaning after the next feature. | ⬜ |
| `face_at` | `point` [x, y, z] and optional `direction`: with a direction, the first face the ray from the point meets (a pick); without, the face nearest to the point. Answers the name, alias, description, the point on the face and the distance. | ⬜ |
| Edge description | `edges` lists `[edge, kind, length, alias]`; the alias is `<alias A>\|<alias B>` when both faces have one. `detail` adds the middle point and, for lines, the direction. | ⬜ |

### 3.6 Security

| Item | Behaviour | Status |
|---|---|---|
| Local only | stdio only; no network listener in phase 1. | ✅ |
| Files | Only the paths the client passes are read or written (open, save, export); relative paths resolve against the server's working folder. With `CADCRAFT3D_MCP_ROOT` set, a path whose folder lies outside it is refused. | ✅ |
| Read-only mode | `--read-only` (both binaries, also with `--attach`): only tools that read (queries, `measure`, `physical`, `export`, `status`, `cancel`) and, headless, `project_open` (the server's own copy) are listed and run; any other is refused with `<Command>: refused, the server is read-only`. Per-command permissions come later. | ⬜ |
| App connections | Off until the user turns on Tools › AI Connector › Allow AI connections (saved in the options). Only the current user: a named pipe (Windows) / a socket in the user's folder (Unix) and a random token written to the user's settings folder that the bridge must send first. | ⬜ |

### 3.6a Action log

| Item | Behaviour | Status |
|---|---|---|
| Journal lines | Every tool call (headless and attached) writes one line `kind: "ai"` into the session's action journal (`diagnostics::journal`, Help › Save Diagnostics): `source: "ai"`, tool, command, the arguments, ok, the error text or the answer (cut to 2000 characters; queries log no answer). | ⬜ |
| Headless sessions | `3dcadcraft-mcp` / `--mcp` start a diagnostics session of their own (log + journal in the logs folder; nothing on stdout). | ⬜ |
| Replay | `ai` lines are ignored by the replay (the state lines after attached calls are the GUI's own). | ⬜ |

### 3.7 Long work, errors, answers

| Item | Behaviour | Status |
|---|---|---|
| Worker | Every `tools/call` except `status`, `cancel`, `project_save`, `undo`, `redo` runs on a worker thread (64 MB stack, kernel panics caught) on a copy of the session; only a success is taken back, as one Undo step. | ✅ |
| Progress | With `_meta.progressToken` the server sends `notifications/progress` about once a second while the work's report changes (feature k of n, stage). | ✅ |
| Cancel | `notifications/cancelled` for the running call, or the `cancel` tool: the copy is dropped, the project is unchanged; the abandoned worker finishes in the background and its result is thrown away. | 🟡 the kernel's work is not stopped (needs the cancel flag of `part::progress`, branch background-ok) |
| Other calls while busy | Queued and run after the running one. | ✅ |
| Errors | Tool failures are results with `isError: true` and the text `<Command>: <reason>` (0-ui wording); unknown tools / methods are JSON-RPC errors (-32602 / -32601). | ✅ |
| Compact answers | Lists as short arrays; `detail: true` where more exists. | ✅ |

### 3.9 Hosted by the running app

The owner watches the agent work in the window and can Ctrl+Z every step (decision 2026-11-19).

| Item | Behaviour | Status |
|---|---|---|
| Turning it on | Tools › AI Connector › Allow AI connections (off by default, kept in Application Options). While on, the app listens on a local pipe for the current user (§3.6). | ⬜ |
| Bridge | The client's config starts `3dcadcraft --mcp --attach`; it connects to the app, sends the token, then passes each JSON-RPC line both ways. The app answers initialize, tools/list, ping and resources from the same table. | ⬜ |
| Status indicator | The status bar shows `AI` while connections are allowed (clients connected in the tooltip) and `AI: <command>` while a call runs; nothing when the connector is off. | ⬜ |
| Calls | Each call goes to the main thread; changing calls run through the background job of spec 0.19 §3.3 on a copy of the project (the view stays usable) and are taken back as one Undo step `AI: <command>` (a batch is one step). Reads run at once on the main thread. | ⬜ |
| User editing | Refused with `<Command>: the user is editing (<what>); try again when it is closed` while a command, a sketch or a background job of the user is open. | ⬜ |
| Project tools | `project_new` / `project_open` are refused when attached (the user's tabs are not the agent's to replace); `project_save` saves the user's file like Ctrl+S; Undo / Redo are the app's own (they also undo the user's steps). | ⬜ |
| Cancel | `cancel` / `notifications/cancelled` cancel the running AI job like Esc. | ⬜ |

## 4. Browser / editing behaviour

Nothing is shown while headless. A saved file opens in the GUI with the features in the browser,
editable as if made there (the tools call the same operations).

## 5. Edge cases and errors

- A handle of another sketch, a region index past the list, a face or edge name not on the
  body: `<Command>: no …` with a hint at the query tool to use.
- A dimension that over-constrains: refused (no driven dimension is made).
- A cancelled call never touches the project, also when its worker finishes later.
- A panic in the kernel: the call fails, the server goes on.

## 6. Implementation

- `src/api/session.rs`: `Session` (project, path, active document, `command::History`).
- `src/api/tools.rs`: the tool table (`Tool`: name, command, description, `Effect`, schema, run),
  `call` (copy → run → commit), `run_on` / `finish` for workers, batch, project tools.
- `src/api/part.rs`, `src/api/asm.rs`: part and assembly tools over `PartDocument` /
  `AssemblyDocument` operations.
- `src/api/mcp.rs`: the stdio server (reader thread, worker, progress, cancel, resources).
- `src/mcp_main.rs`: the headless binary; `src/main.rs` `--mcp`.
- `src/api/names.rs`: face descriptions, aliases, `resolve_face`, `face_at`.
- `src/api/log.rs`: the `ai` journal lines.
- `src/api/host.rs`: the local pipe (`interprocess` local sockets: a named pipe on Windows, a
  socket file on Unix), the token, the `--attach` bridge, the app side's connection threads
  handing calls to the main thread.
- `src/gui/ai_connector.rs`: the Tools menu entry, the status indicator, `ai_tick` (once a
  frame: takes queued calls, refuses them while the user edits, runs them as background jobs).
- Checked by hand 2026-11-19: `tools/mcp_drive.py` drove the built `3dcadcraft-mcp` (initialize,
  37 tools, plate + 4 M8 clearance holes + a corner fillet, physical, save; 0.26 s); the saved
  file opened in the GUI with Extrusion1 / Hole1 / Fillet1 in the browser, 120 × 80 × 10 mm, Valid.
- Checked by hand 2026-11-19: a 40 × 40 hole pattern on a 400 mm plate sent progress
  notifications ("Cut with 1599 tools"), `status` and `ping` answered while it ran, `cancel` after
  2.5 s answered at once and the pattern call got "Pattern: cancelled; …"; `features` showed the
  part without it.
- Tests: `tests/mcp.rs` (every tool through `api::call`, the ROADMAP E plate over the real
  protocol, batch atomicity, cancel).
