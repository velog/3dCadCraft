# 0.18 Themes and colour management

## 1. Purpose

One place decides every colour of the program, and the user can change them. Two independent choices,
as in Inventor's Application Options › Colors:

- **UI Theme**: the frame around the view (ribbon, browser, panels, dialogs, status bar, icons);
- **In-canvas Color Scheme**: the graphics window (background, grid, highlights, sketch colours,
  previews).

The colours' *meanings* stay fixed (0-ui §2.2: a fully constrained curve, a sick feature, a removed
volume). A scheme may change their shades; a new built-in scheme must keep them distinguishable.

## 2. Inputs

None from the model. These are application settings, never document data (rule 8: a part looks the same
for the next user only through its own appearances).

## 4. Browser and editing behaviour

No browser nodes. A change applies at once in the preview and in the program on Apply / OK, without a
restart. Undo does not cover settings.

## 5. Edge cases and errors

- A settings file from an older build lacks the new keys: every missing colour takes the theme's default
  (`layout::lenient`, field by field).
- A custom scheme file with a bad colour value: that element keeps the default, the rest load, and the log
  says which element it was. Rule 5: nothing else in the settings changes.
- Removing the scheme in use falls back to the default scheme.
- Drawing sheets stay black on white in any theme: a sheet is paper, and PDFs must not follow the theme.
- Red back faces stay red in every scheme (0-ui §2.1: they mark an orientation bug).

## 6. Implementation

`gui/theme/`:

- `tokens.rs`: `Tokens`, every named colour of the frame; the built-in `dark()` and `light()` palettes;
- `scheme.rs`: `CanvasColors`, every named colour of the view; `ELEMENTS` with group and translucency flag
  (their keys are file format: never rename one); built-in schemes, user schemes as one JSON file each in the
  settings folder's `color_schemes/`;
- `colors_tab.rs`: `ColorsUi`, the Colors tab and the editor;
- `mod.rs`: fonts, egui's style, drawn symbols, button kinds, `panel_footer`.

A colour drawn in the view takes `theme::canvas()`, one on the frame `theme::tokens()`: a sketch's state is
both (`sketch_view_color`, `sketch_color`).

Steps, each its own change:

1. `Tokens` with the Dark values of today, `theme::tokens()` for the current ones. No visible change.
2. Move the frame's literal colours to tokens, file by file, then add Light. A test fails for a new
   `Color32` literal outside `theme/`, with a shrinking list of files still allowed.
3. `CanvasScheme`: renderer background (gradient), grid, highlights, previews, then the sketch colours.
4. The Colors tab, the editor, Export / Import.

Rule 15 applies to the tab: it is built complete first, with options without logic disabled.
