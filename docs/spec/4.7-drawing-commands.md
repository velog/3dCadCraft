# 4.7 Drawing commands: the complete Inventor command set (interface first)

Status: ✅ done · 🟡 partial · ⬜ to do · ⛔ blocked by another feature.

> Owner's request (2026-10-26): every drawing tool of Inventor as a placeholder first: BOM / parts list,
> balloons, dimensions, tolerances, welding, model reference, which model the BOM comes from, hole
> tables and the rest. Then the logic, command by command (rule 15). This spec lists the whole command
> set and each command's dialog. The commands already working (Base / Projected / Section / Detail /
> Auxiliary View, Dimension, Hole and Thread, Text, Leader Text, Center Mark, Centerline, sheets, PDF)
> are specified in [4-drawings.md](4-drawings.md); styles in [4.6-drawing-styles.md](4.6-drawing-styles.md).

## 1. Purpose

The drawing environment's ribbon carries Inventor 2027's full command set, in Inventor's tabs and panels.
Every command opens its dialog with all of Inventor's options, defaults and selectors. You can try the
dialogs, and selectors take picks on the sheet. **OK and Apply stay disabled** until the command's logic
exists, so nothing changes the drawing (rule 5).

## 2. Inputs

- The command set is Inventor 2027's Drawing ribbon: tab › panel › command.
- Dialog options come from Inventor Help 2027 (sources in §7). Rows marked *(to confirm)* come from
  general Inventor knowledge and are checked against the help before their logic is written.

## 4. Browser and editing behaviour

- A planned command's dialog is a floating window (it remembers its place). The first selector is
  active. A click on the sheet becomes a pick: the geometry under the cursor (point, edge, circle of a
  view), else the view, else the sheet point. The next empty selector then becomes active, as in
  Inventor. Picking the same item again removes it; `x` clears a selector.
- The status bar shows the active selector's prompt.
- Cancel, the window's close button or Esc over the sheet close the dialog.
- Double-clicking a dimension opens Edit Dimension.

## 5. Edge cases and errors

- Nothing is created: OK and Apply are disabled and explain why in their tooltip.
- A planned dialog closes when the document changes (`DrwUi::reset`).

## 6. Implementation

- `gui/drawing_planned.rs`: `Planned` (one variant per command), `Planned::pages` (tabs and rows as
  data: `Row::Sel / Check / Radio / Combo / Num / Text / Head / Note / Button`), `PlannedDialog` (values
  per tab and row, picks per selector, auto-advance). Numbers use `ExprValue` (rule 13).
- `gui/drawing.rs`: `DrwCmd::Planned`, `DrwUi::planned`, `planned_window`, picks in `drawing_viewport`.
- `gui/commands.rs`: `dp(..)` entries (id, name, Bulgarian name, icon, alias, ribbon place).
  `gui/ribbon.rs`: the Place Views, Annotate and (in a drawing) Manage panels in Inventor's order.
- Tests: `every_planned_command_has_a_dialog_and_a_command`, `selectors_advance`, plus the registry
  tests (aliases, ribbon places).
- When a command gets its logic, it moves to its own `DrwCmd` and to 4-drawings.md. Its row here then
  points there.
