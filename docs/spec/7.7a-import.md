# 7.7a Import (STEP; AnyCAD-like)

Status: ✅ done · 🟡 partial · ⬜ to do · ⛔ waiting for another feature. A new spec: everything ⬜.

## 1. Purpose

Bring models from other CAD systems into a part or an assembly. This is how an Inventor user
migrates to us: existing parts and supplier models arrive as STEP. Inventor's **AnyCAD** offers two
modes:

- **Convert Model**: a one-time translation. The result is a *base feature* (bodies without
  history) that further features build on.
- **Reference Model**: keeps a link to the source file. When the file changes, Update translates it
  again and re-matches the faces, so features, constraints and drawing annotations on them survive.

We read STEP with our own reader (`vendor/solidcraft-kernel/src/step_in`, written from ISO 10303-21
and AP203 / AP214 / AP242). Native formats of other systems (SolidWorks, CATIA, NX, Creo, `.ipt`)
are closed and are not planned. IGES / SAT / Parasolid have no reader yet.

## 2. Inputs

- **3D Model → Create → Import** in a part (alias `IMP`), or **Manage → Insert → Import**.
- **File → Open** of a `.step` / `.stp` file: a new part document in its own tab, containing one
  Import feature (Inventor: Open → Import CAD Formats).
- **Assemble → Place Imported CAD Files** (alias `PI`): an assembly (stage I2).
- In the panel: **Browse...** for the file, then the options below. OK reads the file.

## 4. Browser and editing

- One node **Import1** (Inventor shows the base feature under the file's name). The tooltip gives
  the file name, its bodies and the warnings.
- Edit Feature opens the panel with the stored options. Browse... replaces the embedded file. Face
  names stay the same where the STEP face entities are the same.
- Deleting the feature removes its bodies. Features that reference them become sick (health).

## 5. Edge cases and errors

- Not a STEP file, or unreadable: `Import: <reader's reason>`. Nothing changes (rule 5).
- A file with no solids (and Surfaces off): `Import: the file has no solids (turn on Surfaces?)`.
- Faces the kernel cannot build are left out; the body becomes a surface body (an open shell), and
  the warning names how many were left out.
- Very large files: the reader caps counts and depth (untrusted input). Reading runs once per
  regeneration chain thanks to the build cache and the reader's own recent-file cache.
- Reading runs on a worker thread first (a window with the seconds and **Cancel**); only a file
  that reads gets a feature. A 4.4 MB Creo assembly that never finished (ROADMAP K7, a mesher
  loop on revolved B-splines) now reads in 1.1 s.
- A closed body of the file that is no valid solid for us (non-manifold edges, broken loops)
  comes in as a surface body, and the log says so (Inventor imports damaged solids as surfaces).

## 6. Implementation

- `kernel::exact::step_bodies(text, prefix)`: `sk::step_import_shared`, then each body becomes an
  `ExactSolid`:
  - the first body is named `<prefix>`, the next ones `<prefix>#2`, `#3`, …;
  - each face is named `<body>:F<entity>`, where *entity* is the STEP `ADVANCED_FACE` id
    (`face_origin`). The id is fixed for the embedded text, so names survive any rebuild. Pieces of
    a face split by the kernel share the name;
  - a body that is not closed is a surface body.
  The function also returns the bodies' labels, colours, paths and the reader's warnings.
- `part::import::ImportOp` = `BodyOp::Import` (format revision 42). Fields:
  - `file`: the source path, shown in the panel;
  - `text`: the embedded STEP, `Arc<str>` so clones of the part stay cheap;
  - `solids`, `surfaces`: the object filters.
  Regeneration appends the new bodies to the solids and surface bodies built so far.
- `assembly::import::step_project` (stage I2): the file's product tree as documents; each part's
  Import embeds only the entities its solids reach, cut out of the source text with their
  representation (units) by a small exchange-structure index (`P21Index`): the face entities, so
  the face names, stay the file's own and the part is in the product's coordinates. Writing the
  bodies out again through the kernel was tried first and lost faces of a supplier file (one body
  invalid, one 2.5 % short).
- GUI:
  - the Import panel of `gui/part_planned.rs` gets its logic through `gui/surface_cmd.rs`;
  - Place Imported CAD Files (`asm_planned`, same options) places the file at the assembly's
    origin as one Undo step (`gui/import.rs::place_imported_ok`, on a copy of the project);
  - Browse... opens the file dialog (`DialogPurpose::ImportCad`, `*.step;*.stp`);
  - File → Open of a STEP file makes a new part with the feature.
- Tests:
  - an exported box and a filleted part read back with the same volume and face count;
  - face names are stable across regenerations and a save / load;
  - surface bodies come from open shells;
  - a later Fillet on an imported edge works;
  - an error leaves the part unchanged;
  - compat fixture `tests/compat/r42/`;
  - a perf case.
