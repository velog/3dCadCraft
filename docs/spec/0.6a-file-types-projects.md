# 0.6a File types per document and design projects

## 1. Purpose

Inventor keeps every document in its own file, and the file's extension says what it is: a part, an
assembly, a drawing, a presentation, and a *project file* that tells the program where the design's
files live. A user recognises a file in Explorer by its extension and icon alone. Until now we had one
extension (`.3dcadcraft`) for everything, and a file could hold several documents.

This spec gives each document kind its own extension (owner's choice 2026-10-26) and adds Inventor's
**project** — a small file naming the workspace folder, library folders and other locations — together
with the *active project* that the Home page (spec [0.17-home.md](0.17-home.md)), New, Open and Place
work in.

Our extensions (never Inventor's own):

| Document | Inventor | Ours | Notes |
|---|---|---|---|
| Part (also sheet metal) | `.ipt` | **`.ccpart`** | a sheet metal part is a part (Inventor: same extension, other template) |
| Assembly | `.iam` | **`.ccasm`** | links its parts by relative path (spec 3.1, already the model since 2026-10-23) |
| Drawing | `.idw` / `.dwg` | **`.ccdrw`** | |
| Presentation | `.ipn` | **`.ccpres`** | document kind still to come (FEATURES 3.x) |
| Project | `.ipj` | **`.ccproj`** | a text file (JSON), not a model |
| Design file | — (Pack and Go makes a folder / zip) | **`.3dcadcraft`** | many documents in one file — the default way to keep a design (owner, 2026-10-27; spec [0.6b](0.6b-multi-document-files.md)); also Pack and Go, diagnostics and recovery |

## 2. Inputs

- the document kind when saving (Save / Save As);
- a path when opening (Open, Home, drop, command line);
- the project file chosen on Home or in the Projects editor.

## 3. Options and behaviour

### 3.1 File types

| Option | Inventor behaviour | Ours | Status |
|---|---|---|---|
| One document per file | every model file holds one document | a `.ccpart` / `.ccasm` / `.ccdrw` file is the same ZIP container as `.3dcadcraft` with exactly one document; the manifest says its kind | ⬜ |
| Extension follows the kind | Save As offers the extension of the document's kind | Save As of a part proposes `<name>.ccpart`, of an assembly `.ccasm`, of a drawing `.ccdrw` | ⬜ |
| Open filter | *All Inventor Files* plus one filter per kind | *All 3DCadCraft files* (every extension above), then one per kind; the Files of type list becomes a choice | 🟡 Open, Link File and Insert Document list `.3dcadcraft`, `.ccpart`, `.ccasm`, `.ccdrw` (*3DCadCraft files*); a dropped file of any of them opens; the per-kind choice ⬜ |
| Wrong extension | a file is read by its content | loading reads the manifest, never trusts the extension; a `.ccpart` that holds an assembly opens as an assembly with a warning in the log | ⬜ |
| Old `.3dcadcraft` files | — | open as before (all documents in tabs as today); Save keeps the package; *Save As* proposes the single-document type of the active document | ⬜ |
| Package (Pack and Go) | Pack and Go copies a model and its references to a folder / zip | File → Save Copy As → Package `.3dcadcraft`: the active document and every file it references, in one file | ⬜ |
| Assembly links | the assembly stores references to `.ipt` / `.iam` files | Place lists `.ccpart` / `.ccasm` (and old `.3dcadcraft`) files; links stay relative paths | ⬜ |
| Drawing links | a drawing references the model files of its views | a drawing's views reference `.ccpart` / `.ccasm` files by relative path (today: documents of the same project) | ⬜ |
| Icons | each kind has its own icon in Explorer | the app's icons per kind in our dialogs and on Home; Windows file associations (installer) later | 🟡 the file dialog and Home show the kind's icon; file associations ⬜ |
| Format revision | — | the extensions need no format change (the container is the same); older builds open them when the file is renamed or picked through *All files* | ⬜ |

### 3.2 Design projects (`.ccproj`)

| Option | Inventor behaviour | Ours | Status |
|---|---|---|---|
| Project file | text file next to the design data; paths in it are relative when inside its folder | JSON `<name>.ccproj`; paths relative to its folder when inside it | ⬜ |
| Default project | always present, cannot be deleted, no fixed workspace; meant for trying things out | built in (not a file): workspace = `Documents\3DCadCraft`, no libraries; active on the first start | ⬜ |
| Active project | exactly one; it decides where files are looked for, which folders the file dialogs start in and what Home lists | `settings.json` key `projects.active` (path, or none = Default); the title bar / Home show its name | ⬜ |
| Changing the active project | only with every document closed | Home's project list: refused with a message while documents with changes are open; unchanged ones are closed | ⬜ |
| Project list | the projects the user has created or browsed to | `settings.json` key `projects.known` (paths); missing files are shown greyed with "not found" | ⬜ |
| New project (wizard) | name, folder, workspace; single-user or vault | New Project: name + folder → writes `<folder>\<name>.ccproj` with workspace `.`; single-user only | ⬜ |
| Workspace | the folder where the user edits and saves files | `workspace` (one folder); New/Save As start there | ⬜ |
| Workgroup | shared folder searched after the workspace (legacy) | — not planned | ⛔ (vault / shared work, later) |
| Libraries | read-only folders of standard parts | `libraries`: list of {name, path}; Place lists them; their files open read-only | ⬜ |
| Frequently Used Subfolders | shortcuts shown in the file dialogs | `shortcuts`: list of {name, path}; shown in the Places pane | ⬜ |
| Folder Options: Design Data (styles), Templates, Content Center Files | per project or `[Default]` from Application Options | `templates`, `styles`, `content_center` (none = Application Options default) | ⬜ |
| Old Versions To Keep On Save | default 1; −1 keeps all; copies in an `OldVersions` folder | `old_versions` (default 1, −1 = all) into `OldVersions\<name>.<n>.<ext>`; today we keep one `.bak` | ⬜ |
| Using Unique File Names | when a reference is not at its stored place, search the whole project by name | `unique_names` (default false) | ⬜ |
| Search order | workspace, then libraries, in their listed order | `DesignProject::search(name)` in that order, after the stored relative path | ⬜ |
| Included project | another project file merged in | — not planned | ⛔ |
| Projects editor | dialog with the list of projects on top and the selected project's settings as a tree below | Home → `...` → Settings, and File → Projects: list + settings (rule 15: the full dialog first) | ⬜ |

## 4. Browser and editing behaviour

The active project is not part of a document: switching projects never changes a file. A document
opened outside the active project's folders opens with a warning in the status bar (Inventor warns
that the file is not in the project's search paths).

## 5. Edge cases and errors

- A `.ccproj` that cannot be read: it stays in the list, greyed, with the reason in the tooltip; the
  Default project becomes active.
- A project whose workspace folder is missing: activation offers to create it.
- Two known projects with the same name: both listed with their folders.
- A `.ccpart` holding several documents (made by hand): it opens like a package.
- Saving a part to `.ccasm` by a typed name: the extension is corrected to the document's kind, with a
  status-bar note (`Save As: a part is saved as .ccpart`).

## 6. Implementation

- `src/document/filetype.rs` (🟡 code + tests): `FileType` (extension, document kind, display names, filters),
  `FileType::from_path`, `FileType::for_kind`.
- `src/document/design_project.rs` (🟡 code + tests, no GUI yet): `DesignProject` (serde, additive), `load` / `save` (atomic),
  `search`, the built-in Default; the list and the active one live in `settings.json` (`projects`).
- GUI: `gui/files.rs` (filters, Save As extension), `gui/home.rs` (project list), Projects editor
  window.
